# 工作协议

本文件定义任务协作顺序，不重复对象语义。

## 捕捉

1. 用户明确发起后立即建立原始思考会话并保存触发消息。
2. Agent 直接回应用户正在思考的内容；后续可见消息按顺序保存。
3. 链接、文件和召回只是上下文，不抢占前台。
4. 只有问题会实质改变理解时才询问，一次只推进一个关键问题。
5. 用户说“只记录”时立即关闭，不生成闪念。
6. 结束前可以询问是否需要闪念草稿，但不能自动正式化。

## 闪念辨析

- 目标是判断是否值得继续占用注意力，不是把闪念写完整。
- 合法结果：放弃、发酵、形成认识，或超期失效。
- 活跃讨论不会在中途因时钟到点失效；讨论结束后再记录结果。
- Agent 可以发现价值、重复与缺口，不能替用户决定价值。

## 认识完善

- 可以从正式闪念进入，也可以由用户成熟判断直接进入。
- Agent 只讨论当前真正缺少的理由、边界、反例或不确定性，不使用固定问卷。
- 正式写入前必须展示完整候选，并由用户认领。
- 一次讨论允许形成零张、一张或多张永久认识。

## 上下文召回

1. 先按身份、状态、时间和显式形成依据过滤。
2. 再做标题和正文全文检索。
3. 只有基础检索经常漏掉真实相关内容时，才考虑语义候选。
4. Agent 只选择少量真正影响当前讨论的内容，并说明相关原因。
5. 没有相关内容时明确返回没有找到；失败时继续当前对话。

默认优先有效永久认识；发酵闪念必须标明尚未完成；待辨析闪念只在辨析场景出现；放弃和失效闪念默认排除；原始会话和外部来源不代表用户当前立场。

## 统一来源登记

1. 调用者只提交原始引用、材料类型、带入者、上下文和持久化意图。
2. Kernel 解析规范身份并查询现有来源。
3. 已有身份增加引用或关系；没有才创建 `pending_fetch` 来源。
4. 身份不确定时只保存 `pending_identity` 引用，不猜测性创建来源。
5. 内容获取只为既有身份增加快照版本，不能反向创建第二个来源。
6. 用户当前表达、既有闪念和原始会话永远不通过来源登记。
