# Good Idea 两个核心 Skill 产品定义

> 文档性质：产品定义与需求基线，不是运行时规则。发生冲突时以 `规则/` 为准。
> 形成日期：2026-09-25。
> 核心原则：简洁、灵活；规则优于实现，使用优于固化。

## 一、产品目标

Good Idea 不追求保存更多内容，也不让 AI 替用户完成思考。它帮助用户完成两个关键认知动作：

1. **保护正在发生的认识**：保住想法刚刚出现、仍在演化的认知现场。
2. **发展一个值得继续推敲的认识**：判断已保存的想法是否值得投入注意力，并把有价值的部分发展为能够长期使用、质疑和修订的认识。

```text
认知正在发生
      ↓
Skill 1：保护正在发生的认识
      ↓
原始思考记录 + 可选正式闪念
      ↓
认知保鲜期
      ↓
Skill 2：发展一个值得继续推敲的认识
      ↓
放弃 / 发酵 / 永久认识
```

两个 Skill 的划分依据是认知成熟阶段，不是文件类型，也不是内容新旧。

## 二、共同原则

### 2.1 价值单位是认知活动

成功首先表现为：

- 用户能够自然表达，不需要先理解系统结构；
- Agent 延续用户的问题意识和逻辑方向；
- 系统处理没有打断、扭曲或取代表达；
- 用户能够认出候选确实来自本次共同思考；
- 有价值内容进入后续发展，低价值内容退出默认召回。

文件、卡片和关系只是认知活动留下的结果。

### 2.2 严格边界与柔软部分

必须严格保护：

- 原始对话不能被整理结果替代；
- 外部材料不能冒充用户认识；
- Agent 生成的候选不能自动成为正式对象；
- 正式闪念和永久认识必须由用户认领；
- 永久认识必须能返回真实形成现场；
- 状态变化和认识修订必须保留历史；
- 来源获取和召回失败不能导致当前表达丢失。

可以保持灵活：

- 一次会话产生多少闪念；
- 是否调用历史召回；
- 讨论持续多久、追问多少次；
- 相近内容如何合并或拆分；
- 存储、索引和检索如何实现。

### 2.3 人机共创与作者权

Agent 可以通过复述、区分、比较、反例、历史内容和外部材料帮助认识成形。候选可以包含对话中真正共同形成的新理解，不必是用户原话的逐字摘录。

但必须区分：

1. **原始思考记录**：实际发生过的完整可见对话；
2. **候选**：Agent 对共同推理结果提出的结构化表达；
3. **正式对象**：用户看过、理解并明确认领的当前认识。

候选未经认领，始终只是候选。

## 三、正式对象与闪念生成记录

### 3.1 有意思

松海明确认为值得留下、未来可能使用或继续判断，但尚未认领为正式闪念、永久认识，也不要求立即建立完整来源快照的内容。

- 它可以保存工具、网站、仓库、模型、产品、提示词、方法素材、案例或参考方向；
- 新记录默认是 `待处理`；
- 它不代表松海已经形成判断，也不等于外部来源的原文快照；
- 有了实际处理结果后记录去向，原记录继续保留。

有意思登记是直接协议能力，不增加第三个核心 Skill。

### 3.2 闪念

闪念包含生成过程记录和松海认领后的正式闪念，两者不是并列对象。

#### 3.2.1 原始思考记录

原始思考记录保存一次由松海明确发起的连续思考，包括完整可见消息、顺序、时间和必要上下文。它位于 `数据/记录/闪念/原始思考记录/`，只服务于闪念生成过程，不是独立的正式内容对象。

- 一次明确发起对应一份记录；
- 不在表达过程中按语义分支拆成多份记录；
- 一份记录可以产生零个、一个或多个闪念；
- 没有形成闪念不代表捕捉失败；
- 以 Markdown 保存完整对话，摘要不能替代原文。

#### 3.2.2 正式闪念

松海认领、愿意在认知仍然新鲜时继续辨析的候选认知。

它可以表现为问题、矛盾、直觉、异常观察、尚未完成的判断或突然形成的连接。

最小语义包括：

- 能唤起它的标题；
- 松海认领的核心内容；
- 真实触发情境；
- 必要时说明它为什么来自某份原始思考记录或外部材料，并附对应文档链接。

这些内容不是要求松海填写的表单。Agent 应从完整记录中保留，只有关键缺失会严重改变理解时才询问。

### 3.3 永久认识

松海当前愿意反复调用、接受质疑，并允许未来根据新证据修正的一项阶段性判断。

它应当：

- 有相对清楚的核心判断；
- 脱离原始思考记录后仍能理解；
- 说明松海暂时接受它的必要理由；
- 在确有需要时说明边界、反例或不确定性；
- 用自然语言说明真实形成原因，并在原因中附上对应文档链接；
- 获得松海明确认领。

“永久”表示获得长期参与思考的资格，不表示永远正确。正式文件中的生命周期只使用 `有效` 和 `已停用`；修订表现为版本历史。

### 3.4 外部来源

外部来源保存可稳定识别的外部材料、原始引用和实际取得的内容快照。它只说明材料说过什么，不代表松海赞同或吸收。

## 四、Skill 1：保护正在发生的认识

- Skill ID：`goodidea-capture`
- 用户心智名称：灵感捕捉

### 4.1 产品目标

以尽可能小的干预保护正在生成的认知现场，防止想法消失、失真、被过早整理，或者被 Agent 带向另一条逻辑。

它不负责证明想法有价值，也不负责立即形成永久认识。

### 4.2 触发边界

以下情况触发：

- 用户明确要求记录、捕捉或保存当前想法；
- 用户明确续接一个已有捕捉会话；
- 用户带着链接或文件表达自己的想法，并明确要求记录这段思考。

以下情况不触发：

- 只保存外部资料，没有表达自己的思考；
- 记录待办、行动承诺或普通文件操作；
- 审查和发展一张已经存在的闪念；
- 普通问答或事实查询；
- 用户没有表达捕捉意图的日常聊天，即使其中出现了疑问、矛盾、直觉或连接。

普通聊天中出现明显认知种子时，Agent 可以在用户自然停顿处非阻塞地建议一次捕捉。建议本身不触发 Skill；只有用户确认后才建立会话或写入文件，并只补入确认明确涵盖的前序可见消息。用户拒绝或忽略后，本轮上下文不重复建议。

### 4.3 主流程

1. 从用户明确触发的消息开始建立原始思考记录，先保存表达，不先要求标题、分类、卡片类型或去向。
2. 同一现场中的完整可见对话持续追加。即使出现分支，也不在认知发生时拆分会话。
3. 优先回应用户正在思考的问题；附件、来源处理和历史召回只能作为背景。
4. 用户还在展开时继续听；只有关键歧义会产生实质不同理解时才询问一个问题。
5. 用户说“只记录”“先别整理”时，保存并结束，不提问、不提炼、不生成候选。
6. 在自然结束点，只有用户主动要求，或确有清晰种子时，才询问是否需要闪念候选。
7. 用户可以修改、合并、拆分或拒绝候选；只有用户认领后才保存正式闪念。
8. 捕捉完成后停止，不自动进入第二个 Skill。

### 4.4 干预程度

| 表达状态 | 默认行为 |
|---|---|
| 小而清晰 | 简短确认，允许直接保存 |
| 小而模糊 | 最多询问一个决定性歧义 |
| 大而清晰 | 等待用户表达完整后再讨论保存 |
| 大而模糊 | 询问先保存当前现场，还是继续展开 |

该矩阵是启发式，不是固定流程。用户明显还在表达时，不能用矩阵打断用户。

### 4.5 输出和成功标准

一次调用可以产生一份原始思考记录、零张到多张正式闪念、必要来源登记及其形成依据。

成功表现为：

- 用户无需理解系统即可开始表达；
- 完整对话和触发情境没有丢失；
- Agent 没有明显打断或带偏讨论；
- 候选延续用户原有问题意识和逻辑；
- 附件和召回没有抢占认知前台；
- 零产出仍是合法结果。

## 五、Skill 2：发展一个值得继续推敲的认识

- Skill ID：`goodidea-distill`
- 用户心智名称：卡片沉淀

### 5.1 产品目标

先判断一项认识是否值得继续占用注意力，再针对真实认知缺口进行发展，并为它确定明确去向。

成功不等于生成永久认识。放弃、发酵和暂时无结论都可以是合法结果。

### 5.2 触发边界

以下情况触发：

- 用户选择一张正式闪念继续辨析；
- 用户开始处理保鲜期内的待辨析闪念；
- 当前讨论重新激活一张旧闪念；
- 用户要求把候选认识发展成长期判断；
- 用户已经拥有成熟判断，希望直接形成永久认识；
- 用户要求修订或停用一项既有永久认识。

成熟判断不强制先创建闪念，也不适用闪念保鲜窗口。

新想法捕捉、纯资料保存、普通检索和事实问答不触发本 Skill。

### 5.3 认知保鲜期

正式闪念从用户认领时开始进入保鲜期，初始默认值为 48 小时。

- 48 小时是可调默认，不是硬边界；
- 保鲜期用于恢复兴趣、问题意识和隐含上下文；
- 不要求把每张闪念转成永久认识；
- 活跃讨论不会因计时到点而中断；
- 完全未经辨析的 `待处理` 闪念超期后进入 `已失效`；
- 失效不删除历史；
- 用户可以主动重新激活。

提醒和后台调度不属于 Skill 本身。

### 5.4 主流程

1. 读取当前对象和必要形成现场，恢复当时的问题意识，不把旧表达当作当前立场。
2. 先由用户判断是否值得继续。Agent 可以指出重复、异常、冲突和可能价值，但不能代替用户裁决。
3. 只有当前判断依赖历史内容时，才召回少量、相关、可解释的上下文。
4. 确认值得继续后，围绕实际缺口推进，可能涉及核心判断、必要理由、其他解释、边界、反例或未来作用。
5. 已经清楚的部分不重复询问；一次只推进一个会改变理解或决定的问题。
6. 根据用户决定记录去向：放弃、保持未决、进入发酵，或者形成永久认识候选。
7. 进入发酵时保存一段自然语言备注，记录当时真实存在的原因、缺口或重启条件，不强制三项齐全。
8. 形成认识时展示完整候选及真实形成依据。用户可以修改、拆分、合并或拒绝。
9. 只有用户认领后才创建正式认识或新修订版本。

“充分发展”表示真实缺口已经得到足够处理，不表示篇幅必须长或所有维度必须填写。

### 5.5 合法结果

1. **放弃**：转为 `已放弃`，保留历史，默认退出召回。
2. **保持未决**：保鲜窗口内继续保持 `待处理`。
3. **进入发酵**：转为 `发酵中`，保存自然语言备注。
4. **形成认识**：展示一项或多项候选，用户认领后创建正式永久认识。

### 5.6 成功标准

- 用户能重新进入形成现场；
- 用户完成真实价值判断；
- 有价值内容得到实质发展，而非仅被润色；
- 无价值内容退出默认召回；
- 发酵备注能够支持未来重新进入；
- 永久认识能够独立理解、使用和质疑；
- 召回改善判断，而不是增加信息噪声。

## 六、可插拔能力

### 6.1 上下文召回

召回答的问题是：为了理解和推进当前问题，此刻哪些过去内容真正值得重新进入上下文？

- Skill 1 默认克制；
- Skill 2 按实际缺口调用；
- 没有明确帮助时不召回；
- 失败时继续当前对话；
- 结果必须带身份、状态、时间和来处；
- 旧内容不能自动写成当前认识；
- 旧母题只作为旧项目只读上下文，不成为 v0.16 新对象。

### 6.2 统一来源登记

来源登记不是第三个 Skill。

- 用户带材料表达想法时，Skill 1 先保护表达，再登记材料；
- Skill 2 使用实际外部材料时，复用已有来源或统一登记；
- 用户只保存资料时，直接执行来源登记，不触发核心 Skill；
- 来源获取失败不能影响当前认知工作；
- 外部材料永远不代表用户立场。

### 6.3 有意思登记与处理

有意思登记也不是第三个 Skill。

- 用户明确说“有意思”、值得留下以后再看时，直接按有意思协议保存；
- 只保存实际内容、链接和松海已经表达的动机，不为了完整而补写；
- 不自动启动原始思考记录或闪念保鲜窗口；
- 后续实际登记来源、形成闪念或认识时，记录真实去向，不删除原记录。

## 七、衔接和边界

- Skill 1 不替 Skill 2 判断长期价值；
- Skill 2 不假设每张闪念都值得发展；
- 用户认领闪念后，只是获得进入 Skill 2 的资格；
- 48 小时只提供保鲜窗口，不替用户决定；
- Skill 1 结束后不能自动继续追问；
- Skill 2 形成候选后仍需用户认领；
- 原始会话、闪念和永久认识始终分别保留。

规则层负责对象身份、状态、作者权、保鲜期语义、召回资格和历史保护。Skill 只负责触发、加载规则、组织对话、停止和交接，不复制产品规则或数据字段。

## 八、验收场景

### Skill 1

- 用户说“先帮我记下来”，随后说“只记录”；
- 用户长时间表达，Agent 不过早总结；
- 用户表达只有一个关键歧义，Agent 只问一个问题；
- 一次会话形成零个或多个闪念；
- 用户带链接表达想法，解析失败但对话继续；
- 用户只保存链接，不误触发 Skill；
- 普通聊天出现认知种子时最多建议一次，确认前不写入；
- 召回失败不影响完整记录。

### Skill 2

- 用户判断闪念没有价值并放弃；
- 用户认为值得保留但条件不足，进入发酵；
- 用户暂时不能决定，保持 `待处理`；
- 一条闪念形成一项或多项永久认识；
- 成熟判断直接形成候选，不制造闪念；
- 超期闪念退出默认队列但仍可重新激活；
- 既有永久认识的修订形成新版本，停用只改变生命周期状态；
- 召回区分当前认识、未完成闪念、原始现场和外部来源；
- 用户拒绝候选时，不产生正式对象。

## 九、非目标与当前默认

两个核心 Skill 不负责普通聊天自动保存、纯资料收藏、待办管理、思维画像、通用知识图谱、自动价值判断、固定问题数量、后台提醒或绑定具体检索技术。

当前默认决策：

- 正式长期对象统一称为“永久认识”；
- 发酵使用一段自然语言备注，不强制三项齐全；
- 旧母题只作为旧项目只读上下文；
- 48 小时是可配置初始默认；
- “只记录”只保存原始现场，不生成候选；
- 成熟判断可以直接进入 Skill 2；
- 有意思登记、召回和来源登记不增加核心 Skill 数量；
- 第一版 Skill 保持轻量，不预设脚本、应用或复杂执行内核。
