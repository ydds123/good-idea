## 二、阶段 0：事件契约探针

先只读检查 Hermes 的文档、配置、钩子示例和日志：

```bash
rg -n "hook|hooks|post.?turn|turn finished|session_id|turn_id|assistant|user|visible|transcript" "$HOME/.hermes" 2>/dev/null
```

找到真实的回合后钩子入口后，做最小探针。探针只记录事件字段、时序和耗时：不调用 `capture.py`，不写 `数据/记录/`，不记录系统提示、思考过程或工具调用正文，失败写独立探针日志并返回非零，不阻塞回复。

至少用真实回合核实：

1. 是否能取得最终展示给用户的 Agent 回复原文；
2. 是否能取得本回合用户可见消息；
3. 是否有稳定 `session_id`；
4. 是否有 `turn_id` 或等价标识；
5. 是否会重复触发；
6. 是否会乱序；
7. 回复失败后是否触发；
8. 钩子同步还是异步；
9. 样本数、p50、p95、最大耗时；
10. `stop` 所在回合的最后用户消息和 Agent 回复是否可靠到达。

事件样例必须脱敏，只保留字段名、类型、文本长度和必要短片段。提交说明写清上述结论、重复/乱序/失败观察、耗时分位数，以及是否具备实现适配器的前提。

若拿不到最终可见回复、无法稳定关联 session、无法判断重复/乱序，或钩子会阻塞回复且无法满足回合后目标，则暂停适配器，只提交探针结论，不猜测。

## 三、阶段 3b/3c：Hermes 回合后适配器

仅在阶段 0 证明事件契约可靠后执行。新增 `工具/hooks/hermes_post_turn.py`；Hermes 专有解析只能在此文件，不能改 `工具/capture.py` 认识 Hermes 字段，不能把 Hermes 配置或内部事件名写入 `规则/`。

适配器每回合后：

1. 读取 session id、本回合用户可见消息、Agent 最终可见回复和时间；
2. 过滤工具调用、思考过程和系统内容；
3. 转成通用事件数组：

```json
[
  {"speaker":"松海","time":"YYYY-MM-DD HH:MM","text":"...","turn_id":"可选"},
  {"speaker":"Agent","time":"YYYY-MM-DD HH:MM","text":"...","turn_id":"可选"}
]
```

4. 通过 stdin 调用 `python3 工具/capture.py append --session <session_id>`；
5. 若 stop 所在回合已落盘且 `capture.py` 已注销 session，再调用 `python3 工具/commit.py <记录路径> --message "capture: <简短说明>"`；
6. 失败写 `.goodidea/tools.log`、返回非零，不回滚记录，不阻塞回复。

在 `工具/README.md` 写明本机真实 Hermes 注册位置和方式，只写接入方式，不写产品规则。更新 Skill：适配器可用时不要求模型逐轮手工 append；不可用时保留现有退路；stop 仍在候选讨论完成、捕捉窗口真正结束后调用。

至少验收：新建捕捉、续接、重复事件、重放、删除 `.goodidea/` 后重放、stop 所在回合、禁用适配器后的手工退路、提交失败时记录仍写入且 status 显示未提交。逐条比对顺序、时间、说话人、原文，并确认不含工具调用、思考过程和系统内容。

## 四、阶段 1d：清理 Hermes Skill 副本

检查 `$HOME/.hermes/skills`。若存在独立的 `goodidea-capture`、`goodidea-distill` 或其他 Good Idea Skill 副本，记录路径后改为指向仓库 `.agents/skills/` 的符号链接或 Hermes 等价引用，删除独立副本，并验证 Hermes 加载仓库版本。若不存在，提交说明写“未发现独立副本”。不要删除无关 Skill。

## 五、阶段 4：来源同步与标签校验

定位旧脚本：

```bash
find "$HOME/.hermes" -type f \( -name 'sync_source.py' -o -name '*source*sync*.py' \) -print 2>/dev/null
```

确认是当前 Good Idea 来源登记能力后，迁入 `工具/sync_source.py`，只修仓库根路径，不扩写产品行为；保持标准库、不得依赖 Hermes 专有字段。

检查是否已有读取 `规则/标签清单.json`、树外/停用/已并入告警、清单结构自检、使用次数和最近使用日期体检。已有逻辑提供清晰 `tags-health` 子命令；没有才新增不超过 150 行的 `工具/tags.py`。脚本只输出事实和告警，改挂、先建后引、并入、停用仍由 Agent 判断。

检查是否硬编码周三 17:00、20 分钟、排除工作会议。若有，把参数迁入 `规则/标签清单.json` 的炒饭会节点，脚本读取，`默认规则.md` 只引用；没有则不新增配置系统。

真实来源登记验收：正常登记、标签告警、清单结构错误、删除 Hermes 旧副本后仓库脚本仍工作、删除脚本后协议仍能手工完成、阈值不散落。

## 六、正式性能测量

必须使用真实 Hermes 日志，不得用估算、脚本耗时或主观感受代替：

```bash
grep "API call #" "$HOME/.hermes/logs/agent.log" | tail -40
grep "tui turn finished" "$HOME/.hermes/logs/agent.log" | tail -20
```

若日志路径或字段不同，先记录实际路径和字段含义，再用等价查询。选同类捕捉场景，改前和改后至少各 3 个样本，尽量保持消息长度、是否续接、召回情况、模型和服务条件相近。

每个样本记录：模型调用次数、输出 token、墙钟时间、工具调用、失败/重试、是否手工 append、是否自动落盘。每组计算平均值和中位数，样本足够时补 p95，并注明缓存、降速窗口和异常样本。自动适配器未启用时，不能声称捕捉回合变快；样本不可比时结论写“无法判断”。固定加载清单和自动转录收益分开报告。
