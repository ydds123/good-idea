# 标签树

标签是材料的**检索线**：同一条线上的材料会被一次取出来。它回答的是「我以后为什么会再想起这份材料」，不是「这份材料该放进哪个盒子」。所以本树不按知识分类学写，而按**材料与我发生关系的通道**划分；取值只来自本树。

## 相关线只有三条

一份材料以后被再取出来的理由，只有三种来源：

| 线 | 判断依据 | 长出来的样子 |
|---|---|---|
| **来源线** | 它从哪来：固定栏目、固定活动、固定作者或机构 | 炒饭会的一期、某个播客的更新 |
| **主题线** | 它讲什么：同一主题会累积多份材料 | 智能体、设计、组织、认知 |
| **用途线** | 它服务于哪件我正在做的事：栏目选题、产品开发、正在写的稿 | 公众号选题、Good idea 系统 |

三条线互斥：一个标签只属于一条线，归属由判断依据决定（来源线看产出来源，主题线看材料内容，用途线看它服务的事）。
三条线也穷尽：任何「再取出来」的理由，不是来源，就是内容，再不然就是用途。

**不进树的东西**（要么复制已有信息，要么不是检索线）：

- 载体与形态（播客、文章、录音、链接）——`source` 字段和标题已经能看出；
- 时间（年份、月份、第几期）——文件名日期和标题已经能看出；
- 一次性话题与随手关键词——见「新增与维护」第 3 条；
- 价值判断（重要、喜欢、待读、待整理）——这不是检索线，而且会随心情变。

## 进入本树的条件

一条线要进树，必须同时过三道闸门，缺一不进：

1. **可判**：登记这份材料时能一眼判断它属不属于这条线，不用猜。判据写在标签后面。
2. **可复现**：这条线会反复出现，不是只出现一次。单次的线索留在材料正文里，不升级成标签。
3. **可提取**：存在一个可预见的取出动作——「把 X 的材料找出来」这件事真的会发生。

## 层级

- 标签可以带一层子标签，写成 `一级/二级`：一级是线名下的主标签，二级是它内部确实分叉出来的分支。
- 一开始只建一级；同一个标签下出现第二、第三份各自成组的材料时，才加二级。
- 最多两层——再深就不像检索线，像分类了。引用时写完整路径。

## 新增与维护

1. **先查清单，命中即用**：登记材料时先在「标签清单」里找匹配的线，命中就照清单里的写法写。一条材料可以同时挂多条线（来源 + 主题 + 用途）：互斥的是线的划分，不是材料能挂几个标签。
2. **没有匹配时先建后引**：在对应线下列出新的标签行、写清判据，单独提交，然后才写进材料记录；不要先写进记录再回填。
3. **建之前过三道闸门**：可判、可复现、可提取。同一线索第二次、第三次出现才值得建；一次性话题不进。
4. **同线内不重叠**：新增前检查同线已有标签；意义重叠就先合并，或降为它的子标签。不允许两条线吃同一批材料。
5. **少动**：只有出现同义重复、或某条线整体结束（栏目停更、任务做完）时才合并、改名或标注停用。低频线索多而不乱是正常的，不为整洁去整理。
6. **命名**：用我检索时会脱口而出的词；不用缩写和代称，不用 emoji 与特殊字符，英文单词之间用下划线。

## 与 flomo 的关系

借鉴它的三条：标签是索引不是分类；支持多级标签（我们只留一层）；结构从使用中生长，先记内容后加标签，一条材料可以挂多个标签。

没照搬的一条：flomo 官方把标签分成「导航」与「线索」，那是**使用频率**上的差别，要长期用过才知道，没法在登记那一刻判定。本树要求登记时就能判断归属，所以改按**相关线怎么来的**划分，把频率问题留给「新增与维护」第 5 条。

少楠个人的 P.A.I.R 骨架（收件箱／领域／项目／资源）是示范用法，flomo 官方也提醒不要照抄；真要用，等「用途线」真的长出材料时再借它的思路，而不是现在铺开。
