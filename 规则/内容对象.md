# 对象契约

本文件定义五类正式内容对象、闪念生成过程记录、临时候选和解释性形成依据。正式 Markdown 只保存当前可读内容与理解它所需的事实；修订过程由 Git 保留。行动和闪念卡片各自保留一个固定的 `status` 属性，用于显示当前生命周期状态；不在卡片中维护状态时间线。

## 正式内容的文件命名

- 正式内容和原始思考记录统一使用 `YYYY-MM-DD-标题.md`，文件名只由日期与人能识别的标题组成。
- 不默认加入日内序号、对象类型前缀或独立对象 ID；当前阶段以文件路径作为自然定位。
- 只有同一天出现完全相同的标题时，才追加最小冲突后缀，如 `YYYY-MM-DD-标题-2.md`。

## 有意思

松海明确认为值得留下、未来可能使用或继续判断，但尚未认领为闪念卡片、永久卡片，也不要求立即保存完整外部内容的内容。

- 可以保存工具、网站、仓库、模型、产品、提示词、方法素材、案例或参考方向。
- 至少保留“保存的是什么”；当时的保存动机、原始链接或产生情境真实存在时一并保留，不为完整而补写。
- 有意思不代表松海已经形成判断，也不等于外部来源的原文快照。
- 没有处理结果时不添加“待处理”占位；登记来源、形成闪念、形成永久卡片或决定不再处理后，才增加一段自然语言去向，并在原因中附对应文档链接。
- 文件日期已经提供保存时间，不另写创建时间或处理历史。

正式入口：松海明确表示某个内容“有意思”、值得留下以后再看，或明确要求保存为有意思。

## 行动

松海已经决定要做、需要在现实中推进或完成的一件具体事情。行动保存于 `数据/记录/行动/`，记录的是松海的行动承诺，不是想法、认识或外部材料里的建议。

- 一份记录只承载一项可以独立推进或完成的行动，至少写清“要做什么”。对象、完成标准、期限、原因或必要上下文只保留松海实际表达过或执行确实需要的部分。
- “以后也许可以做”、外部材料列出的待办、Agent 推断出的下一步都不会自动成为行动；只有松海明确要求记为行动或待办，才创建正式记录。
- 每份行动必须保留一个固定的 `status` 属性，取值只能是 `待完成`、`已完成`、`已取消` 或 `已过期`；新建行动默认为 `待完成`。
- `待完成` 表示仍待推进；实际完成、取消或决定不再做时，分别更新为 `已完成` 或 `已取消`，并在 `## 结果` 中自然说明已经发生的结果。旧项目因行动窗口结束而暂未裁决的记录更新为 `已过期`，不等于完成或取消。
- 行动内容或状态发生变化时直接更新当前正文和 `status` 属性，由 Git 保留旧版；不在卡片中维护状态时间线。已完成、已取消的行动默认不再作为未完成行动召回；已过期行动仅在处理过期承诺时召回。
- 期限只记录时间要求，不等于已经设置提醒。只有松海另行明确要求并实际完成提醒设置时，才能声称存在提醒。

正式入口：松海明确要求把一件事记为行动、待办或任务，或者明确要求更新、完成、取消一项既有行动。

## 闪念卡片

闪念卡片是松海认领、愿意在认知仍新鲜时继续判断其价值的种子。它可以模糊、矛盾、不完整，也可以只是问题、异常或连接。

一条闪念卡片至少应当能够唤起：它在说什么、为什么当时会注意到它，以及应从哪份原始思考记录继续思考。标题、核心内容和触发情境是最小语义，不是要求松海填写的表单。

- 每份闪念卡片必须保留一个固定的 `status` 属性，取值只能是 `待辨析`、`发酵中`、`已放弃` 或 `已形成永久卡片`；新建默认为 `待辨析`。
- `待辨析` 表示松海已经认领，但尚未决定继续发酵、放弃或形成永久卡片；没有明确决定时不得替松海改变状态。
- 松海决定继续保留并等待以后重新激活时，更新为 `发酵中`，并在 `## 去向` 中忠实记录为什么值得保留、当前缺什么或以后从哪里重启。
- 松海决定不再发展时，更新为 `已放弃`，并在 `## 去向` 中自然说明这一决定；原内容继续保留，默认不召回。
- 闪念实际参与形成一张或多张永久卡片，并且永久卡片已经由松海认领后，更新为 `已形成永久卡片`；在 `## 去向` 中说明形成了什么以及为什么有关联，并附对应文档链接。
- 只有松海明确决定要重新判断，才把 `发酵中` 或 `已放弃` 更新为 `待辨析`；有新决定时再更新状态和自然语言去向。
- 时间可以提醒重新查看闪念，但不会自动把它变成 `已放弃`、`已过期` 或其他状态；没有真实决定就不制造状态变化。
- 状态属性只表示当前生命周期位置；修订历史由 Git 保存，不在卡片中维护状态时间线。

正式入口：松海认领一个完整可见的闪念候选。

### 原始思考记录

一次由松海明确发起、用于保护正在发生的思考的连续对话。它保存在 `数据/记录/闪念/原始思考记录/`。

- 保存松海与 Agent 的全部可见消息、先后顺序、时间以及松海带入的上下文。
- 正文以 Markdown 保存；摘要不能替代完整对话。
- 本次记录何时开始、何时结束，由消息时间和对话是否继续直接呈现，不另写“记录中／已关闭”状态。
- 旧记录可以续接，但需要用自然语言说明续接关系并附上原记录链接。
- 记录边界由松海明确发起的捕捉行为决定，不由 Agent 根据语义实时拆分；对话中的分支先保存在同一份原始思考记录中，事后再判断是否形成多个认知单元。
- 一份原始思考记录允许不产生闪念或永久卡片。
- 只有实际形成闪念卡片、永久卡片或外部来源时，才在文末增加自然语言去向；零产出时不留空清单。

正式入口：松海明确要求开始捕捉或继续一个既有原始思考记录。

### 闪念候选

Agent 从当前表达和共同推理中整理出的临时草稿，不是正式内容对象。

- 可以只存在于当前对话，或在得到授权后保存为临时候选。
- 不进入闪念卡片的辨析和默认召回。
- 松海可以接受、修改、合并、拆分或拒绝。
- 松海未认领时，不得因为对话结束而自动转正。
- 候选可以表达本次对话中新形成的理解，不必是松海原话的逐字摘录；但必须与完整对话区分，并让松海知道哪些内容经过了 Agent 组织或推导。

## 永久卡片

松海当前愿意接受、使用并允许未来调用的一项阶段性判断。

- 当前版本至少应能独立表达判断及其必要理由；只有确实影响适用范围时，才补充边界或不确定性。
- 正文直接呈现当前判断，不再套“当前版本”外壳，也不复制一份版本历史。
- 松海认领修订后直接更新当前正文；Git 保存旧版本。确实有助于理解判断如何变化的原因，可以保留在 `## 演化记录`，但不复制整版正文。
- 松海决定不再把它作为当前判断时，在正文开头增加一条自然语言说明；原内容和 Git 历史都不删除，默认不再召回。

正式入口：松海认领一个完整可见的永久卡片候选，或认领对既有永久卡片的修订候选。

## 外部来源

一份带有出处的外部材料。它的职责是保存材料本身，以及理解和返回这份材料所需的客观信息；不记录系统如何取得、识别或处理它。

- 标题、来源和实际取得的内容是最小构成。来源可以是原始链接，也可以是原始文件名。
- 作者和发布日期能够可靠确定时保留；不能确定时直接省略，不猜测、不用空字段占位。
- 正文默认直接保存实际内容，不在外面再包裹原始引用、身份、别名、快照或获取过程。
- 只有内容缺失、截断或图片未取得等异常会影响理解时，才在正文开头增加一条自然语言说明；正常情况不记录获取状态。
- 明显是同一份材料时复用已有卡片，不追加使用记录或审计轨迹；无法可靠判断时不猜测合并。
- 外部来源不代表松海赞同、理解或吸收了其内容，这一边界由规则保证，不在每张卡片中重复声明。

正式入口：统一来源登记。来源只能在松海明确要求保存实际外部材料时创建。

## 形成依据

形成依据说明永久卡片实际上由哪些内容共同形成，可以指向：

- 原始思考记录；
- 闪念卡片；
- 既有永久卡片；
- 外部来源。

形成依据在正文中以自然语言说明“为什么有关联”，并在原因中附上对应文档链接。它不单独列出文件名、独立 ID 或机械依赖。没有真实关联理由时，不添加关联。
