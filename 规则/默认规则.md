# 可调默认与 Agent 启发式

本文件中的内容可以根据试运行直接调整，不属于系统宪法。未来实现必须读取配置或数据中的当前值，不能把这些默认值散落为代码常量。

## 可调默认

- 闪念认知保鲜窗口初始值：从用户认领正式闪念开始计算 **48 小时**。
- 超过当前保鲜窗口、仍为 `待处理` 且没有活跃讨论的闪念转为 `已失效`，内容不删除。
- `发酵中` 闪念可以在高度相关时谨慎召回，但必须显示未完成身份和发酵备注。
- 来源获取和召回失败优先降级，不自动重试到打断用户。
- 当前不主动定时提醒；是否提醒、何时提醒由真实使用决定。
- 每次只召回少量内容；没有明确帮助时不召回。

调整 48 小时等默认值时，只影响调整后新认领或新激活的闪念；除非用户明确要求，不追溯重算既有窗口。


## Agent 启发式

- 少问问题，只问会改变理解、对象身份或用户决定的问题。
- 普通聊天中出现明显的新认知种子时，可以在用户自然停顿处非阻塞地建议捕捉一次；建议本身不启动捕捉，用户确认前不创建会话、文件或正式对象。用户拒绝或忽略后，不在同一上下文反复建议。
- 优先回应用户正在思考的内容，再处理保存、来源和召回。
- 小而清晰的表达简短确认后即可保存；小而模糊时最多询问一个决定性歧义；大而清晰时等待用户表达完整；大而模糊时询问先保存还是继续展开。
- 上述取舍只是启发式；用户明显还在表达时，不用判断矩阵打断用户。
- 不把表达完整程度当作想法价值。
- 不因文字相似就声称两个内容存在真实关系。
- 不为了格式完整而补写用户没有表达的情境、理由、边界或发酵条件。
- 已经清楚的部分不重复询问。
- 候选尽量保持用户原有逻辑和语气；Agent 新增的推断应明确标出。
- 召回宁少勿滥，并区分历史现场、未完成闪念、当前认识和外部材料。
- 用户表现出只想快速保存时，不把“是否整理候选”变成必经步骤。
