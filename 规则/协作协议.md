# 工作协议

本文件只定义协作顺序。不可绕开的边界以 [`系统宪法.md`](系统宪法.md) 为准；对象身份、字段、状态、转换条件和后果以 [`内容对象.md`](内容对象.md) 为准；可调取舍以 [`默认规则.md`](默认规则.md) 为准。

## 捕捉协议

进入条件：用户明确表示要记录、捕捉、保存当前想法，或明确续接已有思考现场。Agent 在普通聊天中的捕捉建议不构成进入条件，用户确认前不得创建会话或写入任何捕捉数据；用户确认后，可以把确认明确涵盖的前序可见消息作为带入上下文保存，不扩大到无关聊天。只保存外部资料时直接进入统一来源登记，不建立原始思考记录。

1. 立即建立或续接原始思考记录，先保存触发消息。
2. Agent 直接回应用户正在思考的内容；后续全部可见消息按顺序保存。
3. 链接、文件、来源处理和历史召回只作为上下文，不抢占前台表达。
4. 只有答案会实质改变理解或下一步时才提问，一次最多推进一个关键问题。
5. 即使对话出现多个分支，也不在认知发生时拆分会话；完整现场保存后再讨论候选如何拆分或合并。
6. 用户说“只记录”时，确认已经记录并关闭本次窗口；不再提问、不生成候选、不建议下一步。
7. 在自然结束点，只有用户主动要求，或当前会话确有清晰认知种子时，Agent 才询问是否需要整理闪念候选；未经用户认领，不产生闪念卡片。
8. 候选可以表达对话中真正共同形成的新理解，但必须让用户看到完整候选并保留与原始现场的区别。
9. 一次会话可以零产出，也可以形成多个彼此独立的候选。

## 闪念卡片辨析协议

闪念卡片的状态、转换条件和去向要求以 [`内容对象.md#闪念卡片`](内容对象.md#闪念卡片) 为准。本协议只规定如何形成并落实松海的判断。

1. 先呈现闪念卡片原文、触发情境和必要形成上下文，帮助松海重新进入当时的问题现场。
2. 先判断是否值得继续投入，再决定是否完善；语言新奇、信息量和表达完整度不能代替价值判断。
3. 只讨论会改变价值判断的异常、连接、重复、缺口、未来作用或反例。
4. Agent 可以指出可能价值和重复，但不能替松海决定去向。
5. 松海作出决定后，按对象契约同步更新当前状态和自然语言去向；没有决定时不制造状态变化。
6. 永久卡片实际创建且经松海认领后，再按对象契约更新参与形成的闪念卡片。

## 永久卡片完善协议

正式入口和对象要求以 [`内容对象.md#永久卡片`](内容对象.md#永久卡片) 为准；本协议只规定候选如何形成并由松海裁决。

1. 明确用户当前真正想成立的判断。
2. 根据实际认知缺口决定问题数量，可能涉及必要理由、其他解释、边界、反例、不确定性或未来作用；已经清楚的部分不重复询问。
3. 展示一份完整候选，清楚区分原始表达与 Agent 的组织、比较或推导。候选可以包含对话中真正形成的新理解，但不能伪装成用户早已持有的观点。
4. 用自然语言说明为什么有关联，并在原因中附上对应文档链接；不单独列机械依赖或文件名清单。
5. 松海可以认领、修改、拆分、合并或拒绝候选。
6. 松海认领后，按对象契约创建永久卡片或更新既有永久卡片；Git 保留更新前后的正文。
7. 一次讨论允许形成零项、一项或多项永久卡片。

## 上下文召回协议

只有历史内容可能实质减少重复解释、暴露冲突或改善当前判断时才召回。

1. 先按 [`内容对象.md`](内容对象.md) 规定的对象身份、当前状态、形成依据和召回后果过滤，再应用 [`默认规则.md`](默认规则.md) 的召回取舍。
2. 再检索标题和正文；基础检索被真实使用反复证明不足后，才考虑语义候选。
3. Agent 只选择少量真正影响当前讨论的内容，并说明为什么相关。
4. 原始会话只作为历史现场，外部来源只作为材料，行动只作为松海要推进的事情；不得改变这些对象的身份。
5. 没有相关内容时明确说没有找到；检索失败时继续当前对话，不要求松海等待或重新表达。

未纳入 [`内容对象.md`](内容对象.md) 的旧项目母题和其他内容只能作为只读历史上下文，不因此成为新的对象或写入口。

## 行动登记与处理协议

适用范围和正式入口以 [`内容对象.md#行动`](内容对象.md#行动) 为准。

1. 先按对象契约区分松海已经作出的行动承诺，与想法、可选方向、外部材料中的建议或 Agent 推断；不满足正式入口时不创建行动。
2. 查询是否已有同一项未完成行动；明显相同时更新原记录，不能确定时不猜测合并。
3. 按对象契约保存实际存在且执行需要的内容，不为了格式完整追问或补写。
4. 只有缺失信息会使行动无法执行或指向错误对象时，才询问一个决定性问题；其余情况先记录。
5. 行动承诺发生变化时，按对象契约同步更新当前正文、状态和实际结果。
6. 松海明确要求提醒时，另行调用可用的提醒能力，并分别确认行动记录与提醒设置的真实结果。
7. 行动登记不建立原始思考记录，不触发两个核心 Skill，也不把行动自动升级为闪念或永久卡片。

## 有意思登记与处理协议

对象身份、正式入口和内容要求以 [`内容对象.md#有意思`](内容对象.md#有意思) 为准。

1. 先保存松海实际带入的内容、链接和真实保存动机；没有表达动机时不补写。
2. 处理外部材料时，分别判断是否满足有意思和外部来源的正式入口，不因存在链接就改变对象身份。
3. 松海以后决定处理时，再调用对应对象的协议。
4. 只有实际结果已经发生时，才按对象契约更新去向；转为其他对象不会删除有意思记录。

## 统一来源登记协议

对象身份、正式入口和内容要求以 [`内容对象.md#外部来源`](内容对象.md#外部来源) 为准；本协议只规定取得、去重和写入顺序。

1. 先取得材料实际内容，同时识别对象契约需要的客观信息；不能可靠确定的信息不猜测。
2. 查询已有外部来源；明显是同一份材料时复用现有卡片，不能确定时不猜测合并。
3. 按对象契约保存实际取得的内容；无法取得正文时不编造。
4. 同一材料后来取得更完整内容时直接补全当前卡片；Git 保存修订历史。
5. 用户主动带入材料用于当前捕捉时，允许登记为本轮上下文；其他场景需要明确保存意图。Agent 另行发现的材料只有在松海同意持久化后才能登记。

## 规则演化协议

1. 在真实使用记录中写下具体场景、预期、实际结果和摩擦。
2. 判断问题属于单次异常、启发式、可调默认、工作协议还是硬边界。
3. 优先调整启发式或默认值，并继续试运行。
4. 同类问题反复出现后，才修改协议。
5. 只有涉及作者权、内容身份、单一入口、历史保护或规范权威边界时，才修改系统宪法。
6. 规则修改后，在 `规则决策记录.md` 记录原因和生效日期，更新引用该规范的验证场景；其他文件不复制新的规则正文。
