# 决策记录

本文件只记录规则为什么改变及其生效时间，不重复现行规则正文。每项决策如仍影响当前行为，应链接对应的规则归属章节；历史记录本身不参与现行规则裁决。

## 2026-09-26｜Agent 入口补齐规范归属与维护路由

- Agent 入口新增 `规则/README.md` 为必读的规范归属索引，使 Agent 在读取具体对象和协议前先确定权威文件与解释顺序。
- Agent 入口明确区分产品使用任务和仓库维护任务：前者进入 Skill 或直接协议，后者不进入产品 Skill，而是先定位唯一归属再修改。
- 产品规则变更必须执行 [`协作协议.md#规则演化协议`](协作协议.md#规则演化协议)；现行规则无法回答时记录为待验证问题，不由实现、模板或验证材料自行补成规则。

## 2026-09-26｜规范定义改为单一归属

- 松海指出，同一规则分散在对象契约、协议、Skill、模板和验证文档中，会形成多个出口，增加调整成本并产生不一致风险。
- 系统宪法因此增加“规范必须单一归属”的硬边界；[`规则/README.md`](README.md#文件职责) 作为职责索引，指定每类问题的归属文件。
- 本次收敛不改变对象、状态或协作行为，只删除非归属文件中的规则副本，改为引用、执行说明或测试断言。

## 2026-09-26｜闪念卡片增加状态机并统一永久卡片命名

- 闪念卡片状态机的现行定义归属于 [`内容对象.md#闪念卡片`](内容对象.md#闪念卡片)，后续调整只修改该对象契约及引用它的验证断言。
- “永久认识”统一更名为“永久卡片”，同步更名目录、模板、链接和规则术语；历史正文中的真实表达不因命名调整而改写。

## 2026-09-25｜两个核心 Skill 进入试运行

- 产品讨论明确了两个稳定且不同的认知意图：保护正在发生的认识，以及发展一个值得继续推敲的认识。
- 项目创建 `goodidea-capture` 与 `goodidea-distill` 两个轻量 Skill；它们只负责触发、规则加载、对话组织、停止和交接，不重新定义产品规则。
- 上下文召回和统一来源登记是可插拔能力，不增加核心 Skill 数量。
- 纯资料保存不触发捕捉 Skill；成熟判断可以直接进入沉淀 Skill，不强制先创建闪念。
- 两个 Skill 仍处于真实试运行阶段，可以根据路由冲突和上下文负担调整、合并或删除，而不改变对象身份和数据历史。

## 2026-09-25｜双核心 Skill 对齐时补全规则

- 这次规则修订来自双核心 Skill 产品定义与实施审查的对齐，不是已经由真实试运行反复证明的摩擦；因此相关行为仍需在试运行中验证，不能因写入规则就视为产品效果成立。
- 捕捉只接受用户明确的记录、捕捉、保存或续接意图。普通聊天中的明显认知种子只允许在自然停顿处建议一次；用户确认前不得创建会话、文件或正式对象，避免自动发现变成静默记录。用户确认后，可以保存确认明确涵盖的前序可见消息，既保住刚才的思考，又不扩大记录授权。
- 原始思考记录以松海明确发起的连续捕捉行为为边界，不根据对话中的语义分支实时拆分。这样优先保存认知发生的完整过程，把拆分和归纳留到表达结束后。
- 闪念候选允许包含人机共同推理中真正形成的新理解，但必须和原始对话分开显示，并继续由用户决定是否认领，避免把“非逐字摘录”误判为“Agent 可以替用户立场”。
- 闪念卡片增加最小语义要求，是为了能够重新唤起内容、注意它的原因和形成现场；这些语义由 Agent 从对话中保护，不转化为要求用户填写的表单。
- 闪念辨析明确先判断是否值得继续投入，再决定是否完善，避免语言润色和信息补齐替代价值判断。
- 永久卡片完善的问题数量由真实认知缺口决定；理由、其他解释、边界、反例、不确定性和未来作用都只是可能维度，不构成固定问卷。
- 旧项目中的母题和其他非核心内容只作为只读历史上下文，因为新项目不把旧分类继续固化为 v0.16 对象或写入口。
- “小/大、清晰/模糊”的干预矩阵进入可调启发式，是为了减少打断而不是规定流程；用户仍在表达时，矩阵必须让位于当前对话。
- 捕捉结束时，只有用户主动要求或确有清晰认知种子才询问闪念候选，避免把每次记录都推向加工和转化。
- 项目使用 `.agents/skills/` 是为了遵循当前 Agent 平台的项目级 Skill 包装约定。复用目录位置和 `goodidea-` 命名前缀不代表继承旧项目架构；对象、规则、流程和实现仍由本项目独立定义。

## 2026-09-25｜移除机械层

## 2026-09-26｜外部来源增加相关标签与标签树

- 实际使用发现，外部来源只保留来源、作者、日期与正文时，材料之间缺少可聚合的相关维度：同属「炒饭会」的录音笔记散在 6 月以来的不同日期，除了日期和标题看不出共同归属。
- 因此新增可选字段「相关标签」，取值只来自 [`标签树.md`](标签树.md)；标签只表达来源、标题、日期看不出来的相关维度，不重复记录载体信息。
- 标签树的增长规则：先匹配现有节点，命中即引用；没有匹配时先在标签树新增节点（单独提交），再写入记录，不临时造词、不按单篇材料的临时话题建节点。
- 「炒饭会」是第一个节点；识别特征（周三 17:00 后开始的自己录音的分享场，时长与内容类型为辅）属于可调默认，写在 `默认规则.md`。
- 标签树按「相关线怎么来的」分成三条线（来源／主题／用途），每条线下的标签要过三道闸门（可判：登记时一眼能判断；可复现：同一条线会反复出现；可提取：确实存在「把 X 找出来」的动作）；全部标签集中列在 `标签树.md` 的「标签清单」一节。
- 借鉴 flomo 的三条做法：标签是索引不是分类、支持多级标签（只留一层）、结构从使用中生长且一条材料可挂多个标签；但不照搬它「导航／线索」的分法——那是使用频率上的差别，登记时无法判定，所以改按相关线的来源划分。
- 当天补强判据：同线内新增用「差异测试」复核（新标签必须能指出一份只属于它的材料，否则并入既有标签）；三条线各配边界例（像但不算）；停用／合并／退场定为可观察信号（6 个月无新材料且名下不超过 2 份 → 标注停用、旧标签不动；两份标签大面积重合 → 合并）。脚本同步识别清单里的「停用／已并入」标注，登记时告警。
- 主题线落地四个标签（`用AI做产品`／`AI行业观察`／`组织与职场`／`传播与命名`）：逐条过三道闸门与差异测试后写入清单，13 份炒饭会记录回填主题标签（两百期复盘那条不加，内容是栏目复盘，不属于这四条线）。层级一节的措辞同时收紧：二级只留给来源或形态上的真分支，内容主题走主题线。四个名字是 Agent 按手感起的，等松海用自己的词替换。
- 用途线试跑结论：**暂时为空，且判定权写明在松海手上**——某份材料被指派给一件有名字、正在做的事才挂，Agent 不主动猜（材料「与」某件事相关属于主题线）。边界例同步补一行。
- 顺带补漏：清扫未打标签的 16 份材料时发现主题线缺口，新增 `AI设计与生图`（4 份：Anshu Chimala 系三篇 + 热狗 GPT 作图心法），并把三份行业／政策材料挂上既有 `AI行业观察`、一份挂 `组织与职场`；另有四条候选暂缓（来源线 `曾鸣《智能商业》` 只有一章素材、主题线控制论一组名字偏宽泛、用途线 `Good idea 发布` 只有一份、`公众号选题` 待松海判定）。
- 同一晚的多段录音按「合并成一份」登记（松海指定）：主段（时长最长）定标题与 `source`，文件名日期取登记当天、真实场次日期进 `published_at`，正文开头与分段表保留各段的标题、时长与来源。
- 层级改为条件化（松海指示：不要写死层数／条数，「可以有多条，只不过多条要按照条件去设」）：删掉「最多两层」的硬上限，改成每加一级、每加一条都要过同一组条件——① 上一级名下确实有两组材料、取回时会分开找；② 每组不少于 2 份。份数（一级到 10 份左右）只作 Agent 的复查提醒，不作门槛。同一条原则也适用于线的数量：加第四条线要先过 MECE。
- 第一个层级实例落地：`AI行业观察/政策与报告`（3 份：2026 中国企业级 AI Agent 发展洞察报告、“北京智能体新政”解读、2026 WAIC 参展企业 MECE 分层全景 v7），材料引用改挂完整路径。
- 标签树按「机制／内容」分成两份文件，都在规则层：`标签树.md` 只留机制（相关线怎么划、进树条件、层级、维护与退场），新增 `标签清单.md` 只留内容（三条线分组、一行一个标签及其判据与状态），是 `tags` 取值的唯一来源。理由是两者的变更方式与读取时机不同：机制罕见且重（改它要走规则演化），清单常见且轻（每次登记都可能加一行，且每次登记都要读）；放在一份文件里会让日常加标签也背上规则变更的仪式。清单留在规则层而不进数据层（数据层只回答「已经保存了什么」，不定义含义），也放在同一层是为了「标签树里有哪些标签」只有一个地方可看。脚本、技能、模板与规则内引用同步改到新清单。
- `标签清单` 由 Markdown 改为 `规则/标签清单.json`：主要读它的是 Agent 与脚本（每次登记都要读、校验时读），松海读得少，故用机器友好的 JSON 存。结构为「相关线 → 标签（名称／判据／状态／备注）」，状态取值「在用／停用／已并入」。顺带换来两项原来做不到的校验：脚本直接解析 JSON（不再靠「短横线＋反引号」行格式正则，格式漂移不会再静默丢标签），并在体检里自检清单结构——缺名称、重名、子标签缺父级都会报出来。机制文件仍为 Markdown（`标签树.md`），因为机制是供人读与争论的文本。
