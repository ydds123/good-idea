# 规则层

本目录是 Good Idea 当前产品语义的唯一权威来源。单一归属原则以 [`系统宪法.md`](系统宪法.md#系统宪法) 为准；产品定义、原始设计方案、根 README、Skill、数据模板、试运行记录以及未来代码都不能覆盖这里的定义。

## 文件职责

| 文件 | 唯一负责 | 不负责 |
|---|---|---|
| `系统宪法.md` | 不可绕开的边界和最终决定权 | 流程细节、字段和默认值 |
| `内容对象.md` | 对象身份、状态、转换后果、正式内容的人读命名与形成依据 | 对话步骤和底层存储实现 |
| `协作协议.md` | 捕捉、辨析、完善、召回、行动与来源登记的协作顺序 | 重复定义对象状态 |
| `默认规则.md` | 可快速试验的默认值与 Agent 启发式 | 硬边界 |
| `标签树.md` | 相关线怎么划、什么条件能进树、层级与退场等机制 | 具体有哪些标签、字段格式、写入时机 |
| `标签清单.md` | 有哪些标签、每个标签的判据与状态（`tags` 取值唯一来源） | 机制、字段格式、写入时机 |
| `规则决策记录.md` | 规则为何改变、何时生效 | 复制现行规则正文 |

## 单一归属的写作边界

上表同时是规范归属索引。新增或修改规则时，先判断问题属于哪项职责，只在对应文件定义一次。

- 回答“是什么、何时成立、允许哪些值、会产生什么后果”的文字属于规范定义，只能写在归属文件中。
- 其他文件可以写如何调用、如何呈现、如何验证，并通过链接指向归属章节；不能为了方便阅读重新列出完整定义。
- 模板和验证可以出现具体字段或状态值，但它们只代表格式示例、测试输入或预期结果，不因此成为规则来源。
- 决策记录只解释改变原因并链接现行规则，不承担现行值域、流程或边界的持续维护。

## 解释顺序

出现冲突时按下列顺序处理：

1. 先保护 `系统宪法.md` 中的硬边界；
2. 再依据 `内容对象.md` 判断内容身份和状态；
3. 再依据 `协作协议.md` 决定协作顺序；
4. `默认规则.md` 可以为具体场景让路，但必须记录原因；
5. 无法由现有规则回答时，记录为待验证问题，不得由实现偷偷补成产品规则。

## 演化原则

真实使用出现摩擦后，依次判断它是单次异常、启发式问题、可调默认问题、协议问题，还是触及身份与作者权的硬边界问题。优先调整成本低的层级；只有重复证据充分时，才升级规则强度。
