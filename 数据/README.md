# 数据层

数据层只回答“已经保存了什么”，不定义对象应该意味着什么。当前数据层只保留人能够直接阅读和修订的 Markdown 事实，以及历史迁移材料。

## 目录

```text
数据/
├── 记录/                 正式 Markdown 内容
│   ├── 有意思/           值得留下、以后再处理的内容
│   ├── 闪念/             正式闪念
│   │   └── 原始思考记录/ 闪念生成过程的完整思考记录
│   ├── 永久认识/         永久认识及版本历史
│   └── 外部来源/         带有作者、出处等客观信息的外部内容
├── 资产/                 图片与附件
├── 模板/                 Markdown 事实格式示例
└── 旧项目/
    ├── reference.json    旧项目只读位置声明
    └── 迁移历史/          首批迁移的历史材料，不参与日常运行
```

### Markdown 是认知事实

- 原始思考记录保存完整可见对话，不能只存摘要；它属于闪念目录，不是并列对象。
- 有意思保存松海明确要求留下、以后再处理的内容。
- 闪念和永久认识保存松海实际认领的内容。
- 外部来源保存标题、来源、实际内容，以及能够可靠确定的作者和发布日期。
- 来源正文直接进入内容；只有缺失或截断会影响理解时才在开头说明异常，不保留获取过程和快照外壳。
- 人不需要运行程序就能理解已经保存的内容。

## 文件命名

- 正式记录统一使用 `YYYY-MM-DD-标题.md`，例如 `2026-09-25-关于职业选择的讨论.md`。
- 只有同一天出现完全相同标题时，才追加最小冲突后缀，如 `YYYY-MM-DD-标题-2.md`。
- 文件名首先服务于阅读和链接；不放对象类型前缀、序号或独立对象 ID。
- Markdown 内部只保存理解内容所需的状态、时间、正文和解释性链接。
- 关联写成“为什么有关联”加对应文档链接，不单独列机械依赖或文件清单。

## 旧项目参考

`旧项目/reference.json` 声明旧项目的位置和冻结提交。旧项目始终只读。`旧项目/迁移历史/` 只保存已经完成的首批迁移脚本和历史清单，不是当前系统的运行依赖，也不参与新内容创建。

旧项目的历史捕捉会话和讨论日志不迁移。旧内容中的真实触发情境可以随对应正式记录保留，但不得伪造原始思考记录。
