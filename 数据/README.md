# 数据层

数据层只回答“已经保存了什么”，不定义对象应该意味着什么。

## 混合数据模式

```text
数据/
├── 记录/             Markdown：人能够直接阅读和修订的认知事实
│   ├── 原始思考会话/ 原始思考完整对话
│   ├── 有意思/       值得留下、以后再处理的内容
│   ├── 闪念/         正式闪念
│   ├── 永久认识/     永久认识及版本历史
│   └── 外部来源/     外部来源身份与快照记录
├── 资产/             图片与附件；内容哈希命名，不是第六类对象
├── 系统/             JSON：机械支撑状态
│   ├── ID登记/       稳定 ID 登记
│   ├── 临时候选/     临时候选
│   ├── 操作事件/     幂等与操作事件
│   ├── 索引/         可重建索引
│   ├── 缓存/         可重建缓存
│   └── 后台状态/     后台处理状态
├── 模板/             Markdown 事实格式示例
└── 旧项目/           旧项目只读位置声明
```

### Markdown 是认知事实

- 原始思考必须保存完整可见对话，不能只存摘要。
- 有意思保存用户明确要求留下、以后再处理的内容。
- 闪念和永久认识保存用户实际认领的内容。
- 来源记录保存身份、原始引用和实际快照历史。
- 人不需要运行程序就能理解已经保存的内容。

### JSON 只做机械支撑

- JSON 可以帮助稳定寻址、去重、幂等、排队和加速检索。
- 索引、缓存和后台状态删除后应当可以重建。
- JSON 不得保存一份与 Markdown 竞争的“正文真相”。若两者冲突，以 Markdown 事实和不可变事件为调查起点。
- 临时候选即使保存在 JSON，也不会因此成为正式内容对象。

当前没有活动 Kernel。Agent 可以依据规则和模板直接保存 Markdown；等真实使用证明需要确定性写入时，再设计最小执行能力。

## 文件命名

- 正式记录统一使用 `YYYY-MM-DD-NNN-标题名.md`，例如 `2026-09-25-001-关于职业选择的讨论.md`。
- 文件名前不放 `SES-`、`INT-`、`FLA-`、`INS-`、`SRC-` 等对象类型前缀；稳定 ID 只保存在 Markdown Frontmatter 中。
- 日期使用对象真实创建、保存或认领日期；序号按“对象目录＋日期”分别递增。
- Markdown 内部保存完整身份、状态和时间；路径只是组织方式，不是对象身份。
- 模板展示最小结构，不要求为缺失信息编造内容。

当前没有确定性写入器时，Agent 先检查同类对象在当天已经使用的序号，选择下一个未占用的 `NNN`，并在写入前再次确认目标文件不存在。发生冲突时重新读取现有文件并选择新序号，不覆盖已有对象。这个约定只是临时机械做法，不改变任何对象语义。首次出现并发写入、序号冲突重复发生，或项目引入确定性写入器时，就应以原子 ID 分配替代并删除本约定。

## 旧项目参考

`旧项目/reference.json` 声明旧项目的位置和冻结提交。旧项目始终只读，不调用旧业务代码、Skill、状态机或目录设计。经松海明确授权的旧数据可以按迁移清单有条件复制进当前数据层：每条数据必须登记旧路径、旧 ID、文件哈希、目标对象、目标路径、字段转换和验证结果；禁止在迁移清单之外整库复制。

旧项目的历史捕捉会话和讨论日志不迁移。旧内容中的真实触发情境可以随对应正式记录保留，但不得伪造原始思考会话。
