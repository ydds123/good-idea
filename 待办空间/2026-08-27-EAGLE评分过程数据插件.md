# EAGLE评分过程数据插件

## 原始记录

为 EAGLE 图片管理的打分功能做插件：评分时收集过程数据，不只存 12345 星级。

两块内容：
1. 培养看图维度：定义看图/评图的角度（从哪些维度看一张图），训练眼光——看得多了，逐渐筛选出自己觉得高质量的内容；
2. 过程数据保存：看图评分时记录评分依据（为什么给这个分），把判断理由与评分一起存下来。

后续价值：做图时按风格/维度从图库检索素材（想要什么风格的图就从库里找，不靠脑子想）；回看高评分素材时知道当时为什么给高分。

现状：EAGLE 现有评分是 12345 星级量化，过程数据丢失；评分维度可继续拓展。

## 为什么做

评分的本质是以个人主观感受给素材库内容评分，把高质量内容聚合在一起、逐渐筛选出好东西，这也是多看、训练眼光的过程。收集过程数据的目的是帮助后续更好地做图——想要什么风格的图，就从图片库里找，不靠脑子想。过程数据很重要：后续既能看高评分素材，也知道为什么当时给它高评分。

## 产生情境

2026-08-27 晚，松海最近安装了 EAGLE 图片管理工具，觉得它的图片打分小功能有用但可以更丰富。场景：打开收藏的各个图集看图、给图评分时，心里其实有自己的评分依据，但软件最终只落成一个 12345 星级——中间的过程数据（为什么给这个分、从哪些角度看的）丢了。由此想到看东西可以从哪几个角度去看，看图也是一种训练。明确说不急着做，先记下想法。关联前情：Hermes 侧已有 Eagle 相关 skill（eagle-assets、eagle-collection-userscripts）和 eagle-prompt-annotation 油猴脚本（生图站→eagle-annotation 元数据注入），未来实现时可联动。

- 2026-08-27T21:39:38+08:00 — 【2026-08-27 晚追加】看图训练能力的完整场景与新细节：
1. 看图的目的：看图=看别人怎么做，有点像做产品的竞品分析，最终目的是服务于自身的创作需求。
2. 当前困扰：GPT 作图缺乏思路——想作图，但不知道想要什么样的东西。希望通过看图多打开一些思路，后续作图时脑子里的东西起码会多一点。
3. 两件事：①怎么去分析——分析的方法论；②如何将分析内容沉淀到工具里。
4. 痛点：EAGLE 现在的评分是单一评分，只有一个最终结果；希望做插件把评分过程数据存下来（为什么打 3 分、是哪个维度 3 分、总体哪些点不错），后续找某一系列图时有依据，比单一评分更准确。
5. 用户旅程：打开一张图 → 按快捷键 → 输入内容 → 插件基于内容自动拆分（哪些维度、每个维度的分数、每个评分的理由）→ 数据保存 → 构成后续创作时检索的依据。
6. 待调研：Eagle 插件生态是否支持以上场景（可行性）；若可行，如何构建。

- 2026-08-27T21:42:39+08:00 — 【2026-08-27 调研结论】可行性：完全可行。Eagle 4.0 插件生态已具备全部所需能力（官方文档 developer.eagle.cool/plugin-api）：
1. Inspector 插件类型（要求 4.0 Beta 17+，本机 4.0.0 build 23 满足）：选中图片时右侧检查器面板直接展示插件 UI——比快捷键更顺的入口（Eagle 无全局快捷键 API，右键菜单 contextMenu 可作辅助入口）。
2. eagle.item.getSelected() 拿选中项；item.add/modify 可写 annotation 与 tags——评分过程数据（维度/分数/理由）结构化存 annotation、维度可打 tags。
3. AI SDK 官方依赖插件（统一模型配置中心，8 providers，支持 structured object generation）——"输入内容→自动拆分维度/分数/理由"由 AI SDK 的结构化生成实现。
4. 检索：Eagle 原生搜索覆盖 annotation + AI Search 语义搜索 + tags 筛选。
构建方案（MVP 三步）：P0=Inspector 插件+输入框+写 annotation（手动三字段：维度/分数/理由）；P1=接入 AI SDK 自动拆分；P2=检索层验证（annotation 搜索+tags 维度筛选）。本机已有铺垫：eagle-prompt-annotation 油猴脚本（生图站→eagle-annotation 元数据注入）、Hermes 侧 eagle skill（REST API 操作）。

- 2026-08-27T21:47:54+08:00 — 【2026-08-27 设计决策：输入与拆分分工】用户只输入即时看图感受（自由文本），AI 负责拆维度/分数/理由。维度规范约束（松海补充）：拆分目标维度必须来自用户预设的维度体系（受控库）——否则每次拆的维度不在一个规范里，沉淀的数据没法做归类分析。机制同 Good idea 估价受控枚举：AI 把自由文本映射到预设维度上打分写理由；遇到覆盖不了的新维度，列候选等松海确认后再扩展维度库，不得自行发明。

- 2026-08-27T21:48:43+08:00 — 【2026-08-27 设计决策：种子维度清单】种子 9 维：风格、主题/内容、构图、光影、色彩/配色、氛围/情绪、细节/质感、完成度/技术质量、创意/独特性。维度体系必须做成可配置的（松海拍板：后面肯定要做成可配置）——增删改在配置层完成，不硬编码；AI 拆分只映射到当前配置的维度。

- 2026-08-27T21:50:27+08:00 — 【2026-08-27 设计决策：分数语义与分工】制式 1-5 分（1-10 无意义，与 Eagle 星级同制式）。总体分由松海直接打（如"给一张图打四星"），维度分由 AI 基于松海的感受拆分给出——分工语义：总体分=人的直觉裁决，维度分=AI 的分析展开，AI 不替人做总体判断。每个维度分附理由；理由以自由文本为主，另由 AI 提炼"不错的点"清单。总体分联动写回 Eagle 原生星级（星级保留作总体分载体，原生排序筛选继续可用）。
