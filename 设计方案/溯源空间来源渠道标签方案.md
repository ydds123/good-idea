# 溯源空间来源渠道标签方案

> 状态：已定稿（2026-08-13 拍板：实体命名标签 + 隐藏输入框 + 保存对话提问机制；子代理审查 deleg_b138004c 通过，审查修正已融入正文）
> 2026-08-13 子代理（deleg_1e9c439a）基于第一性原理重设计后定稿，废弃原"渠道/载体混打 + 机械推导"方案

## 一、目标

让每张来源卡片一眼可辨"这条信息来自哪个渠道"，代价趋近于零：**不污染内容层、不增加认知负担、不碰快照安全**。

## 二、现状与缺口

- 来源卡片 frontmatter 只有 author / canonical_url / 哈希等字段，没有渠道维度；想筛"我保存的公众号文章有哪些"只能靠人脑记 URL 域名。
- 设计文档《永久卡片整体设计逻辑》的标签思想（"标签是未来的使用场景、少用静态分类"）针对的是**永久卡片的内容语义层**；来源渠道属于**来源元数据维度**（与 author、canonical_url 同类），两者不冲突，但必须声明边界防止越界。
- 概念基线明确：标签只负责补充场景、领域和状态，不承担主要分类职责——来源层打渠道标签符合此原则。
- 实测缺口定位（2026-08-13 子代理核实）：标题/author 已覆盖多数来源的记忆锚点（如李继刚卡 author=MindCode、标题含"李继刚/闭门会"），真正缺的是**标题未带渠道名**的来源（如《AI时代职场自救法则》正文出自"炒饭会第196期"）——标签要补的正是这类增量。

## 三、方案设计

### 3.1 语义与粒度——标签是回忆锚点，不是分类

定位一句话：**标签的唯一价值是匹配未来回忆**（未来检索入口是记忆中关于来源实体的词："炒饭会说过什么""李继刚说过什么"）。核心矛盾：锚点 vs 静态分类。

| 项 | 约束 |
|---|---|
| 打什么 | 实体身份专有名词：渠道品牌（炒饭会）、人物（李继刚）、系列场景（闭门会）——无法从 URL/文件名推导，且是标题/author 未覆盖的增量 |
| 不存什么 | 载体形态（公众号文章/行业报告/网页）：可从域名、文件类型机械确定，符合"可推导信息不存储"既有原则（不存绝对路径、不存分享参数皆为先例）；按形态筛选属视图层（Bases/Dataview 按 `canonical_url` 含 mp.weixin.qq.com 派生列），不占 frontmatter |
| 字段形态 | frontmatter 可选 `tags`，多值字符串列表（JSON-compatible YAML 带引号，如 `tags: ["炒饭会"]`）；**schema 只写弱约束**（可选字段 + 字符串列表），全中文、去重、≤2 条由对话层 Agent 查重维护，不做 lint 校验 |
| 机制 | 不进 ENUM 机制（不预设全集），随积累自然生长 |
| 增量原则 | 先对照标题与 author，只补未覆盖的回忆词；**没有增量的来源不打**（允许不打） |
| 边界 | 不承载内容语义标签（AI、职场这类主题词不打）；schema 写明用途边界，防字段日后漂移 |

### 3.2 机制——用户命名，CLI 记账

- **命名权归用户**：回忆词只有用户自己的记忆知道。Agent 机械推导必得废值（"公众号文章"对所有微信来源是常量）、推不出宝值（"炒饭会"的载体也是公众号文章）——"用户只确认不思考"确认的是自己没参与决策的值，是无效劳动。此为该方案的裁决依据。
- **打标签时机**：`source commit` 的保存对话中顺口一问"这条你未来会用什么词想起它？"；答不上来/说不需要则不打。边际成本≈一句话。用户表示"不用问"后，本轮后续来源默认不打（每轮至多问一次）。
- **Agent 职责**：查重 + 提问，不机械推导。查重数据源 = 现场扫描 `溯源空间/` 全部 `.md` 的 frontmatter `tags` 字段（标签数量级小，不为此新建清单文件；积累到一定量再考虑 CLI 查询命令），提示"已有'炒饭会'，同一渠道吗"，防近义碎片化。
- **场景边界**：标签只产生于前台保存对话与回填；后台来源维护（`--attach-flash-ids`，用户不在场）一律不提问、保持无标签——允许不打原则覆盖。
- **CLI**：新增 `maintain source-tags --source-id <ID> --tags <列表>`，对标现有 `maintain metadata`（幂等事务 + preflight + `replace_frontmatter`），只改 frontmatter、**不触碰快照区、不触发任何哈希变化**。**修正路径 = 重跑同命令**（`--tags` 传新值即整体替换、传空列表即清除），走既有事务/回滚通道，不引入新机制。
- `source preview --tags` 写入 preview JSON；`source commit` 从 preview-file 读取（commit 侧不重复加参数）；tags 补进 `_persistable_source_preview` 白名单（service.py:141-191）——否则被静默丢弃、传了白传。
- `source refresh` 保持现有 no-change 守卫不变：元数据修改一律不经过 refresh；已打 tags 不会被 refresh 冲掉。

### 3.3 呈现与检索

- Obsidian 属性面板**新增 tags 专属 CSS 规则**：对 `data-property-key='tags'` 隐藏编辑控件（输入框），**保留标签渲染与点击搜索**（`tag:` 聚合）。非复用 properties-zh.css 的整行隐藏做法（那是 `display:none`，渲染与点击一起消失）。
- 主入口仍是标题/文件名（规则 11 保证标题即文件名、全文可搜）；标签只承担两类增量：**标题覆盖不到的回忆词**、**跨来源点击聚合**。
- 渠道聚合视图（"所有炒饭会"）属视图层：未来在 Bases 溯源库加一列即得，不做 frontmatter 层面的分类体系。

### 3.4 回填示例（新语义下）

| 来源 | tags | 说明 |
|---|---|---|
| 《AI时代职场自救法则》（正文渠道名：炒饭会第196期） | `["炒饭会"]` | 标题/author 均未覆盖渠道名，聚合增量 |
| 对话李继刚闭门会精华 | 不打 | "李继刚""闭门会"均已被标题覆盖；仅当出现多期闭门会、确有跨期聚合需求时再打 |
| 2026中国企业级AI-Agent发展洞察报告 | 不打 | 标题自足，无增量 |

### 3.5 落地顺序

1. schema.md（通用字段表/内部参数表/各类型字段表三处，tags 弱约束：可选字段 + 字符串列表）+ `.goodidea/baseline/decisions-v0.1.md` 追加记录
2. service.py：白名单补齐 + 新来源 meta 构造 + `maintain source-tags` 命令
3. cli.py + web.py：preview `--tags` 参数（写入 preview JSON，commit 从 preview-file 读取）
4. 测试：白名单透传（覆盖 preview→commit 全链）、tags round-trip、maintain 不动快照哈希、回填幂等（内容零变更）
5. 更新 `goodidea-record-literature/SKILL.md`：纯来源保存流程第 3–5 步间增加标签提问（先确认保存动机、再顺口问"这条你未来会用什么词想起它？"，同一轮对话两问连发；用户答"不用问"后本轮后续来源默认不打）；后台来源维护路径（`--attach-flash-ids`）不提问、不打标签
6. 回填执行（按 3.4 定稿取舍；**绝不重抓网页**）
7. README 命令表 + Obsidian tags 专属 CSS

### 3.6 验收标准

- `maintain source-tags` 重复执行**内容零变更**（git diff 无内容文件变化，仅 state/log/index 事务记录），快照区零 diff
- 回填后快照区零 diff（`git diff` 无 snapshot 区变化），lint/verify 通过
- `source commit --tags` 后 tags 真实落库（白名单透传测试覆盖全链）
- Obsidian 中 tags 隐藏输入框、保留渲染与点击搜索

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 白名单静默丢字段 | 白名单补齐 + 专门测试覆盖，杜绝"看起来做了实际没生效" |
| Obsidian 手痒编辑重写 frontmatter 停摆（08-12 已发生过一次） | tags 专属 CSS 隐藏编辑控件（软防线）+ lint 检出 + 既有恢复流程（git checkout）兜底 |
| 标签碎片化（同一渠道多种写法） | Agent 打标签时查重提示（"已有'炒饭会'，同一渠道吗"） |
| 粒度漂移成维护黑洞 | 语义收窄为实体身份专有名词；Agent 不推导、用户命名、允许不打 |
| 快照安全 | 已核实 tags 不参与 content_sha256/snapshot_sha256，零哈希风险 |

## 五、不做什么

- 不用 refresh 改元数据（机制不通，会诱发重抓）
- 不做标签全集预设、不进枚举机制、不加 lint 校验（弱约束留给对话层）
- 不机械推导标签值（推导得出的必是废值、推不出的恰是宝值）
- 不把载体形态存进 frontmatter（视图层派生）
- 不给永久卡/闪念加 tags（本次只做来源层，闪念标签思路另议）
- 不创建文献笔记层/摘要
