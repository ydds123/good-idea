# 任务：待办行动闭环 v2——摄入澄清 + 48h 过期状态机

> 文档性质：任务交接说明，不是生效规则。由用户指定其他 Agent 执行；执行 Agent 不得自行放宽 AGENTS.md、schema.md 或用户作者权边界。
>
> 交接日期：2026-08-15

## 一句话任务

把待办空间从"只进不出"升级为"行动闭环"：**输入侧**加澄清式捕获（模糊才问、答案进卡片"为什么做"区、估价引用），**状态侧**加 48h 行动窗口（新建=未开始，超 48h 未开始→已过期，移出当前行动清单等待用户裁决），**阅读层**同步（行动清单只显示未开始+进行中）。

## 背景与现状

### 已有机制（2026-08-15 已上线，不要重复造）

1. **估价机制**：`capture valuate` 为进行中待办写入七个标签（需求类型/高阶目标/等效性/多效性/成功概率/距离/具体性）+ priority（期望×价值×距离排序：概率×多效性×距离主键、等效性 tie-break、未估价排最后）。理由必填（`--rationale`，机制拒绝黑箱），渲染成卡片"估价依据"区（对象|内容|说明 三列 Markdown 表格，含确定性得分与优先级）。标签枚举受控（need_type 固定 3 种、goal_id 固定 4 个 GOAL_SPECS），数据库视图下拉单选。
2. **状态归档**：待办状态子目录（`已完成/`、`已取消/`），`capture transition` 流转归档 + 全库 wikilink 重写；`capture sync` 扫描待办（根/已完成/已取消）与闪念（根/已处理）双向归位。
3. **估价 cron**：job `2a39a27def65`，0/8/16 点跑，自动估价新待办；估价前做状态检查（事实已完成/失效的先 transition 归档）。
4. **方法论**：闪念卡《目标规划方法论：目标层级金字塔、目标系统理论（等效性/多效性）与目标特征》（`闪念空间/2026-08-14-...md`）——估价排序、六特征标签的单一事实源。

### 缺口

1. **摄入侧不问为什么**：`capture todo` 直接保存，不追问动机。当前 9 条待办里多条只有标题一句话（如"阅读《Raycast...》"），无"为什么做"，估价靠猜。
2. **无未开始/过期概念**：待办只有进行中/已完成/已取消。事实没开始做的（念头起来 48h 没动）仍躺在行动清单里，不产生行动。
3. **昨晚方案 A 搁置**：`待办空间/2026-08-14-待办行动闭环方案...` 里存有 2026-08-14 拍板的方案 A（未开始档 + 必填原因 + 48h 预警），本次实施吸收它并升级。

## 用户确认的设计（2026-08-15 拍板）

### A. 摄入侧：澄清式捕获

- **触发原则：B（模糊才问）**——用户口述内容已含动机的，直接存不追问；只有一句话/意图不明/无动机信息的才追问。全问会制造流程摩擦。
- **问题集（一次一个，对话式，不是表单）**：
  1. 为什么做这件事？（动机/价值 → 喂需求类型+高阶目标）
  2. 不做会怎样？（损失/机会成本 → 喂值不值得）
  3. 做完是什么样？（期望产出 → 喂具体性）
  4. 打算什么时候做？（时间窗口 → 喂距离+投入规模）
- **落点**：卡片正文顶部新增"## 为什么做"区（用户确认过的原话记录，属于用户认知正文，非 CLI 机械区）。`capture todo` 支持可选 `--reason` 写入该区。
- **估价衔接**：估价 cron prompt 要求先读"为什么做"区；valuate 的 rationale 引用它作为判断依据，不再只靠正文猜。

### B. 状态机：48h 行动窗口

```
新建待办 → 未开始 ──48h 内开始──→ 进行中 ──→ 已完成
              │                      ↑
              │ 超过 48h 未开始       │ 重新承诺
              ↓                      │
           已过期 ──裁决──→ 干掉 → 已取消
```

- **未开始**：新建待办默认状态（替代现在的默认"进行中"）。**计时基准 = 最近一次进入未开始的时刻**（frontmatter `not_started_at`，进入时由 CLI 记录；重新承诺刷新、退出清除）——不是 created_at。
- **进行中**：用户开始做（阅读层数据库视图改状态 / CLI transition）→ 退出 48h 窗口。
- **48h 语义（用户 2026-08-15 拍板）**：48h 是**开始行动的窗口，不是完成的期限**——48h 内只要开始做（哪怕翻一页书）即通过窗口；"未开始"= 还没动起来，动起来就改进行中。学习型待办同样适用，不做类型差异化。
- **48h 过期（确定性 CLI，用户 2026-08-15 拍板）**：新增 `capture sweep` 命令——扫描 `未开始` 且 `now - not_started_at >= 48h` → **已过期**，物理移入 `待办空间/已过期/` 子目录（与已完成/已取消同构，含全库 wikilink 重写）。sweep 是 CLI 确定性命令，不依赖 Agent 判断；由估价 cron（0/8/16 点）顺带调用。已过期从当前行动清单消失。
- **裁决**：已过期待办由用户二选一——**重新承诺**（transition 回 未开始，**必填一句话原因**（2026-08-15 拍板：写入"为什么做"区，防止无脑点一下击穿 48h 约束），移回根目录重新计时）或**干掉**（transition 到 已取消）。
- **呈现通道（2026-08-15 拍板）**：已过期**不在主视图行动清单**，但**灰显置底分组**常驻主视图（一眼可见、可裁决、不占行动清单）——不是隐藏到单独视图，否则用户无通道知道需要裁决，闭环断裂。
- **推送保持不做**（用户 2026-08-15 明确拍板：推送渠道先不用）。过期通过数据库视图灰显呈现。

### C. 阅读层（数据库视图）

- `Good idea 数据库/待办数据库.md`：行动清单 = 未开始 + 进行中（过滤已过期/已完成/已取消），按 priority 排序；状态列 statusOptions 增加 未开始/已过期 语义色（未开始灰/进行中绿/已过期红）。**已过期灰显置底分组常驻主视图**（一眼可见、可直接裁决），不在行动清单内。
- 用户开始做 = 在数据库视图把状态列改为"进行中"，CLI `capture sync` 收口（沿用现有阅读层手动修改模式）。
- 已过期裁决 = 在数据库视图把状态列改为"未开始"（重新承诺，CLI 侧要求补原因）或"已取消"（干掉），`capture sync` 收口。

## 存量迁移（执行 Agent 开工前必须先向用户确认）

1. **计时方式**：9 条存量"进行中"迁到"未开始"后，48h 从**迁移日**重新计时（给存量一次重新承诺机会；用户 2026-08-15 倾向此方案）还是从 created_at 严格算（存量几乎全过期，直接进入裁决）？——先确认再迁移。**迁移实现**：transition 到 not_started 时 CLI 自动写 not_started_at=迁移时刻（存量无此字段，迁移即补齐）。
2. **顺带裁决**：迁移时请用户裁决明显不想做的（如"看板统计"用户自注"不一定要做"），可 transition 已取消。
3. **"开始做"触发**：阅读层改状态 + `capture sync` 收口（沿用现有模式，不加新交互）——确认用户无异议。
4. **自指待办**：本任务自己的待办卡（`待办空间/2026-08-14-待办行动闭环方案…实施.md`）迁移时**保持进行中**（不被 48h 窗口误过期），实施完成后直接 transition 已完成。

2. **不得放宽 AGENTS.md / schema.md**：改 schema、状态机、契约前先向用户汇报具体改动方案，确认后再落地。
3. **修正融入正文，单一事实源**：状态机/澄清流程直接写入 schema/README/Skill 本体，不得以补丁式说明保留新旧两套说法。

7. **推送保持不做**：本任务不引入任何推送渠道（飞书等），48h 过期通过数据库视图呈现。
8. **枚举受控**：新状态/标签枚举值写中文、进 contracts 受控清单；数据库视图 statusOptions 同步。

- 新建待办默认 `status: 未开始` 且带 `not_started_at` 计时基准；摄入内容模糊时 Agent 触发澄清追问（四问），用户确认的答案出现在卡片"## 为什么做"区（`--reason` 写入）
