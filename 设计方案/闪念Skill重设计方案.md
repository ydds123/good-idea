# 闪念 Skill 重设计方案

> 文档性质：设计方案（框架版定稿），非生效规则。2026-08-23 与松海讨论定稿；下一步填充细节并实施到 `.agents/skills/goodidea-capture-flash/SKILL.md`。关联待办：待办空间/2026-08-22-优化闪念-skill.md。

## 一、背景与动机

2026-08-22 捕获「知识库+AI 的形态」闪念时，Agent 产出被连续否定 6+ 轮（要点罗列→丢原话→干巴框架→标注别扭→编号切碎→无结构→逻辑线缺失），暴露现有 skill 的三个核心问题：

1. **双流程割裂**：现有 skill 分「多轮捕获工作流」与「重要信号流程（闪念 Plus）」，共享底层机制却硬拆两套，导致判级前置（多一次「是否走 Plus」的确认交互）、边界模糊。
2. **普通侧缺口**：普通流程只要求「忠实整理」，没有「找齐上下文做针对性补充」的要求——而补充描述、逻辑线是所有闪念的刚需（教训：卡片要能让松海想得起上下文）。
3. **判级依据错误**：「重要」是主观信号，容易误判；本质的结构特征是大小（点线面体）与充分度。

## 二、本质定义

**闪念 = 松海跨域连接的浓缩结果**——脑回路能瞬间连接两个不相关事物的本质（快速得到结果），但过程是压缩的。

**矩阵定位**（两个维度）：

- 大小：点（一个念头）→ 线（串起几个点）→ 面（覆盖一片框架）→ 体（立体结构）
- 充分度：充分表达（已串起来、想清楚）vs 未充分表达（有框架但没串起来，存在挖掘点/可能性空间）

**Agent 的角色 = 展开 + 校验**：把压缩的过程展开（找上下文、把挖掘点挖开、串起来），展开的同时校正结果。**展开的目标 = 从不充分到充分**（矩阵的「充分」维度）。完善表达 = 校正认知。

## 三、主线六步

| 步骤 | 干什么 | 要点 |
|---|---|---|
| 1. 接住 | 原样记录 | 不丢、不改、不打断——现场保护 |
| 2. 定位 | 矩阵定位，**判断后与松海确认** | 大小 × 充分度 → 决定挖多深；确认后才开始找料 |
| 3. 找料 | 按定位找相关上下文 | 过去卡片、来源、资料——挖得深找得全 |
| 4. 展开 | 把不充分展开到充分 | 加工对象 = 原始语料 + 检索内容；挖掘点逐个挖开、串起来、补全、逻辑线揪出来；终点 = 矩阵的「充分表达」；质量标准见「加工检查清单」 |
| 5. 校验 | 完整脉络呈现 | 松海确认/纠正——校正环节 |
| 6. 落盘 | 确认是完整、充分思考的闪念后存下 | 去向由松海裁决：闪念 / 永久卡 / 留档讨论 |

**深度规则**：越大、越不充分的闪念挖得越深；越小、越充分的做得越轻（轻到跳过 3-4 步直接落盘）。

**加工检查清单**（2026-08-22 反馈固化，展开/校验环节对照执行）：

- 不拆平铺要点：保留原话表述与原话逻辑
- 框架 + 血肉 + 逻辑流动，缺一不可
- 针对性补充描述（概念展开 + 逻辑线）融入原文、不刻意标注
- 逻辑线揪出来：说明「为什么把这两件事关联」
- 有结构但不编号切碎，也不能没结构——语义标签式
- 卡片要能独立唤起上下文
- 落盘前必须松海确认（确认门禁）
- 提问纪律：提问与目标关联，成形即停

### 矩阵定位判断标准

**大小（点/线/面/体）——听结构信号：**

- 点：一句话能说完，无展开结构，无连接点
- 线：一个念头带出 2-3 个关联点（想法 + 依据/例子）
- 面：有框架——多个点组成结构
- 体：多个面互相关联（跨域连接成体系）

判断信号：出现「然后/另外/还有」等连接词 → 至少是线；提到多个子主题、有「本质/框架/体系」类词 → 面；引用了过去的卡片/来源、说「这里边其实包含东西蛮多的」→ 面/体；跨域连接（两个不相关领域）→ 体。

**充分度——听表达信号：**

- 不充分：说「挺重要」但没说清为什么；提到概念不展开（「卡帕西那个闪念」）；探索语气多（其实/本质/对吧/怎么说呢）；自我修正多（「到 10 月底……或者说 9 月底」）；出现能连过去的点（「就按照我们前边整理的」）——这些点就是挖掘点
- 充分：有完整的因为所以；自问自答闭环；边界清楚

### 四象限深度参数

| 象限 | 找料 | 展开 | 校验 |
|---|---|---|---|
| 小×充分 | 不找 | 不展开 | 忠实整理，轻确认 |
| 小×不充分 | 轻找（相关卡 1-2 张） | 一次一问补全，把点说圆 | 呈现补全后的点 |
| 大×充分 | 全找（相关卡+来源） | 结构化梳理（脉络+连接） | 完整脉络确认 |
| 大×不充分 | 全找+跨系统（llm-wiki、历史会话） | 深度展开：挖掘点逐个挖开、串起来、补全、逻辑线 | 展开后完整呈现，松海纠正（校正环节） |

### 主线每步具体动作

1. **接住**：capture start 原样保护第一段表达，不打断、不先问
2. **定位**：听完一轮后按判断标准判断大小+充分度 → 向松海确认定位结果（一句话：「这个想法我判断是【面×不充分】——有框架但没串起来，要挖开几个点，对吗？」）→ 确认后才进入找料
3. **找料**：检索锚 = 表达里的专有名词/概念/过去的引用；渐进式读取（先索引/文件名 → 命中读正文），不全量；大×不充分跨系统（llm-wiki、Hermes 历史会话）
4. **展开**：识别挖掘点（提到但没展开的东西）→ 每个点补「是什么」+ 揪「为什么在这里出现/和什么连」→ 按松海原始逻辑顺序串接（不重排）→ 补充融入原文不标注 → 终点检查：每个提到的概念都展开了吗？逻辑线都揪出来了吗？能独立唤起上下文吗？（对照加工检查清单）
5. **校验**：呈现完整脉络（不是碎片清单）→ 松海确认/纠正 → 纠正 = 新输入，回到 3-4
6. **落盘**：确认完整成形后，问去向（闪念/永久卡/留档）→ 走 CLI → 落盘前必须松海确认

## 四、情况补充

**聊到一半**（任何时刻可能发生，跟主线正交）：

- 暂停：capture pause，记录全留，下次 resume 接着聊
- 放弃：capture discard（必须松海明确说），零正式写入
- 中断恢复：capture resume，接着上次的脉络继续

**只想记一下**（小×充分的快捷通道）：

- 接住后直接 capture flash/interesting/todo 落盘，跳过找料/展开/校验
- 存的是待办时附加规矩：B 原则（模糊才问，全问制造摩擦）；四段信息架构（标题/事项/动机/情境），写清「为什么做」

**转永久卡**：

- 不自动转；落盘时松海裁决去向
- 讨论出了结论：先问转不转；转 → 交接 goodidea-form-permanent；不转 → 结论用松海原话 capture revise，讨论原文 capture discuss 留档

**底线（任何时候不能破）**：

- 松海的话就是松海的话：不改意思、不替你总结、不加没表达的观点
- 落盘前必须松海确认
- 讨论留原话，不留 Agent 总结
- 引用的来源标清楚
- 捕获阶段不自动进永久卡

## 五、与现状的差异

| 现状 | 新方案 |
|---|---|
| 双流程（普通 + 闪念 Plus）+ 重要信号判级 | 单一主线，矩阵定位决定深度 |
| 判级前置（「是否重要」→ 确认是否走 Plus） | 定位后置（先保护表达，再矩阵定位） |
| 普通流程禁问定义/因果/边界 | 按矩阵：大×未充分放开问题域（为了展开） |
| 单次轻量记录独立于流程 | 小×充分的快捷通道（同一条主线） |
| 补丁式堆叠（讨论留档/待办澄清/暂停放弃分节） | 主线 + 情况表 + 底线总纲 |
