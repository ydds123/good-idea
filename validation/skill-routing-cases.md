本文件验证 Skill 的触发、排除、停止和交接，不重新定义产品规则。正式语义以 `rules/` 为准。

静态审查日期：2026-09-25。当前 13 个路由用例均能由两个 Skill 的 description 和明确排除条件得到唯一预期入口。自动发现与真实对话效果仍需在新的 Codex 会话和后续试运行中持续记录。

## Skill 1 行为用例

### 只记录

1. 创建或续接原始思考会话。
2. 保存全部可见表达。
3. 用户说“只记录”后只确认保存。
4. 不提问、不生成候选、不交接第二个 Skill。

### 长表达与关键歧义

- 用户明显还在展开时不总结、不拆分会话。
- 一个歧义会造成实质不同理解时，最多询问一个关键问题。
- 仅仅为了补标题、分类或字段时不提问。

### 多个认知种子

- 原始对话继续保存在同一会话。
- 在自然结束点展示可独立修改、合并、拆分或拒绝的候选。
- 未经用户认领，候选不进入正式数据。

### 附件和失败降级

- 附件处理不能抢占用户表达。
- 来源获取和历史召回失败时，当前会话继续。
- 不编造未读取材料中的内容。

## Skill 2 行为用例

### 价值不足

- 用户可以直接决定放弃。
- 内容和历史继续保留，默认退出召回。
- Agent 不要求把它解释成成熟观点。

### 发酵

- 只记录一段忠实的自然语言备注。
- 不强制同时填写保留理由、缺口和重启条件。
- 未来出现时明确标注尚未完成。

### 形成永久认识

- 先完成用户认为必要的价值辨析和认知发展。
- 展示完整候选和真实形成依据。
- 候选可以包含对话中新形成的理解，但不能伪装成用户原有观点。
- 用户认领后才正式创建；原始会话和闪念继续保留。

### 成熟判断直接进入

- 不创建形式性的闪念。
- 不适用 48 小时窗口。
- 只处理独立理解仍缺少的内容。

## 交接验收

- `goodidea-capture` 完成后停止，除非用户明确要求继续辨析或形成认识。
- `goodidea-distill` 不反向复制原始会话，也不把检索结果变成新闪念。
- 来源登记和上下文召回可以被两个 Skill 调用，但不能控制用户结论。
- 删除、重命名或合并 Skill 时，对象身份、状态和数据历史仍然成立。
