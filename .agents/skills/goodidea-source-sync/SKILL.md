# Goodidea 外部来源同步（来源登记）

把得到大脑（Get笔记）里的材料取出来，按数据层格式落进 `数据/记录/外部来源/`：一次脚本调用完成取料、落盘、图片入库、去重、可选提交。

## When to Use（何时用）

- 松海说「把…同步/放到外部来源」「登记这个来源」「把得到大脑里的 X 放进来」
- 材料在得到大脑（Get笔记）：播客链接（小宇宙等）、文章链接、录音笔记（分享会/会议）、biji 分享链接
- 每周三/周四的「炒饭会」例行（见下）

## 边界（不要越界）

- 规则权威在 `规则/内容对象.md#外部来源` 与 `规则/协作协议.md#统一来源登记协议`；脚本只负责执行。格式要改：先改规则，再改脚本。
- 判断不外包给脚本：**选哪些材料**、**作者怎么写**由松海/Agent 决定；`list`/`weekly` 只列候选与疑似。
- 来源登记是非捕捉试运行：落盘后按 `验证/试运行协议.md` 补一份 `验证/试运行记录/YYYY-MM-DD-来源登记试运行.md`（含完整可见对话）。
- 会议/项目类录音（企业微信录音、需求评审）会出现在扫描里，默认不登记，除非松海点名。

## 标签树（机制 = `规则/标签树.md`；标签取值 = `规则/标签清单.json`）

按「材料与我发生关系的通道」分三条线：**来源线**（从哪来）、**主题线**（讲什么）、**用途线**（服务于哪件正在做的事）；一个标签只属于一条线，一条材料可以同时挂多条线。新标签要过三道闸门——可判（登记时一眼能判断）、可复现（会反复出现）、可提取（确实有「把 X 找出来」的动作）。全部标签列在 `规则/标签清单.json`（脚本直接解析 JSON，不再用行格式正则 ``- `标签名` `` 行解析）；子标签只留一层，写 `一级/二级`。脚本做三类校验：树外标签告警；清单里标了「停用／已并入」的标签也告警（新登记不要再用）；`tags-health` 体检（使用次数／闲置节点／清单结构自检）。判断留给松海/Agent：同线内新增先过「差异测试」（新标签要能指出一份只属于它的材料，否则并入既有标签），三条线的边界例与停用信号都在 `标签树.md`。

## 临时需求流程（≤3 回合）

1. （可选）列候选：

   ```bash
   python3 /Users/apple/Documents/Goodidea/工具/sync_source.py list --limit 20 --json
   ```

   看 `registered` 字段：为空的是未登记候选。

2. 一次同步（可多篇，`--commit` 直接提交）：

   ```bash
   python3 /Users/apple/Documents/Goodidea/工具/sync_source.py sync <note_id> [<note_id> ...] --commit --json
   ```

3. 读报告，处理异常（图片失败／作者未定／去重跳过），**并对每条新材料过一遍标签清单**：来源线／主题线／用途线各有匹配就挂上；没有匹配、但这条线索已经是第二次出现，按「先建后引」先加清单节点再引用。这一步不要省——省了会出现「材料都登记了、主题线却一直空着」。
4. 补试运行记录。

## 每周例行（周三、周四）

- 内容：把窗口内（默认「昨天 00:00 起」，覆盖前一晚）与「炒饭会」相关的材料同步进外部来源，命中的打标签；**同一晚的多段录音合并成一份记录**（`--no-merge` 可关）。
- 入口：`python3 ~/.hermes/scripts/goodidea_weekly_sync.py`（cron 调；无内容时输出为空、不推送；有同步或疑似才输出一行）。
- 底层：`sync_source.py weekly --update [--tag 炒饭会] [--commit]`；`--update` 会在下次运行时补全当晚先同步的半成品。
- 判据（2026-09-26 用 6/15 以来 85 条真实笔记校准，权威在 `规则/默认规则.md`）：
  - 自动（周三晚的分享场，13/13 命中、0 误报）：自己录的音（非链接笔记）+ 录音开始于周三 17:00 之后 + 时长 ≥ 20 分钟 + 内容类型不含「工作会议」。
  - 疑似：正文出现「炒饭会」但结构不符（如线下课、链接笔记）→ 只报告，等松海确认。
  - 关键词只作确认信号：13 场里只有 2 场正文出现「炒饭会」，抽查 5 条完整逐字稿有 3 条 0 命中。
  - 时长同样不充分：同一窗口有 122~164 分钟的「工作会议」、151~165 分钟的周末分享、239~240 分钟的线下课。
  - 一晚常被切成几段（06-24、07-01、07-15、07-29、09-02 各 2~4 条，最短 1 分钟）：识别单位是「周三这一晚」，默认只收 ≥20 分钟的段。
- cron：周三 23:30 与周四 09:00 各一次（幂等，重复跑只更新不重复建）。

## 参数

| 参数 | 作用 |
|---|---|
| `list --limit N [--since YYYY-MM-DD]` | 列最近笔记候选 + 是否已登记（含时长、内容类型） |
| `sync <id…>` | 同步一篇或多篇（id 或含 id 的链接都行） |
| `merge <id…>` | 把一晚的多段录音合并成一份记录（主段＝时长最长的一段） |
| `weekly [--since D] [--scan-only] [--no-merge]` | 每周例行：扫描 → 分类（自动/疑似/跳过）→ 同一晚合并成一份 |
| `--tag 名称` | 写 frontmatter 标签，可重复；`--update` 时与已有标签合并 |
| `--weekday N` / `--min-hour N` / `--min-minutes N` / `--exclude-type S` | weekly 判据（默认 2=周三／17 点／20 分钟／「工作会议」；权威 `规则/默认规则.md`） |
| `--keyword 词` | 只用于「疑似」提示（默认 炒饭会），不作判据 |
| `tags-health`（mode） | 标签体检：使用次数、树外标签、闲置节点、清单结构自检 |
| `--dry-run` | 只生成不落盘，打印临时文件路径（可 diff 校验） |
| `--update` | 同一材料已登记时补全/更新现有卡片 |
| `--commit` | 落盘后 git 提交（AGENTS.md 允许直接提交，不推送） |
| `--author TEXT` | 覆盖作者（默认从页面/系列映射推导，推不出就省略） |
| `--no-transcript` / `--no-images` | 不写逐字稿 / 不下载图片 |
| `--date YYYY-MM-DD` | 覆盖文件日期（默认 = 登记当天） |

## 落盘结果（对照规则）

- 目录：`数据/记录/外部来源/YYYY-MM-DD-<材料标题>.md`（日期 = 登记当天，标题 = 材料自己的标题，不用得到大脑的 AI 长标题）
- frontmatter：`author` / `published_at` / `source`（＋可选 `tags`）；确定不了就省略，不猜
- 正文：AI 智能笔记（智能总结／章节概要／金句精选／关键洞察／待办事项）＋ 完整逐字稿 ＋ 节目简介/页面正文
- 图片：下载进仓库 `数据/assets/`（文件名 = 文件字节的 sha256），正文里的链接改写为该目录的相对路径
- 去重：同 `source`、同笔记 id，或主段标题与既有记录相同 → 跳过（`--update` 才更新）；合并记录正文列了各段来源，任一段命中即跳过
- 合并记录（一晚多段录音）：主段（最长一段）定标题与 `source`，正文开头一行说明 + 「当晚分段」表列各段标题/时间/时长/来源，各段智能笔记与逐字稿按段分节（段内标题整体降一级）
- 材料正文里的应用跳转链接（`[时间戳](https://getnotes.seek:N)`）在落盘时统一去掉，只留时间戳文本
- 作者推导顺序：`--author` > 系列映射（炒饭会 → 永道缔生）> 页面「本期主播/本期嘉宾 + 节目名」> 页面 author > 省略
- 标签：可选字段 `tags: [...]`，取值只来自 `规则/标签清单.json`（2026-09-26 生效）；一条材料可挂多个。脚本对树外标签在报告里告警，但不自动打标签。

## 坑

- `getnote` 返回的 JSON 可能含控制字符：脚本用 `json.loads(..., strict=False)`；手工解析时同样处理。
- 转写稿体积大（2 小时录音约 5 万字）：**不要让正文进对话上下文**，看报告的字符数与校验结果就够。
- 页面元数据（发布日期/节目名）依赖外网，失败就省略字段，不要编造。
- 批量（>20 篇）前先 `getnote quota -o json` 看额度。
- 新形态材料（脚本没覆盖的结构）先手工落一份，再把形态补进脚本。
- 列表接口不回 attachments/url：脚本对链接类笔记会补一次详情（拿原始链接和时长），因此 list/weekly 每条多花约 1 秒。
- 时长与内容类型：录音笔记在正文「录音信息」块（`时长`、`内容类型`、`参与人数`），链接类在页面正文的「内容总时长」。

## 实测基线（2026-09-26 建立，本机）

| 动作 | 实测 |
|---|---|
| 单篇播客（1.2 万字正文 + 3 万字逐字稿 + 海报入库） | 1.5 s |
| 单篇录音（2.5 小时、5.2 万字逐字稿 + 1 张图，含 git 提交） | 1.1 s |
| 重复材料幂等（`--update`） | 1.7 s，无提交 |
| `list` 20 条（链接类按需补详情） | 2.4 s |
| `weekly --scan-only` 15 条（含 3 次详情补取） | 8.8 s |
| 周例 wrapper（窗口内无内容） | 8.1 s，输出为空 |
| `weekly --scan-only` 扫 85 条（6/15 以来全部，含详情补取） | 约 100 s |
| `tags-health`（19 份记录体检） | < 0.5 s |
| 补登窗口 06-15 起（扫 85 条 + 10 晚合并 + 10 次提交） | 30.4 s |

对照：同一篇播客的手工对话流程 = 19 次模型往返、3 分 54 秒（同日实测）。经验：转写稿只落盘、不进对话上下文；批量一次调用给多个 id；跑完读报告即止。
