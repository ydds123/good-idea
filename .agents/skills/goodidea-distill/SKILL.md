# 发展一个值得继续推敲的认识

目标是先判断一项认识是否值得继续占用注意力，再针对真实认知缺口进行发展，并为它确定明确去向。

## 先加载规则

1. 始终读取 `../../../rules/constitution.md`。
2. 读取 `../../../rules/objects.md` 中的正式闪念、永久认识和形成依据。
3. 读取 `../../../rules/protocols.md` 中的闪念辨析、认识完善和上下文召回协议。
4. 涉及保鲜期、发酵或召回取舍时读取 `../../../rules/defaults.md`。
5. 正式保存或修改对象时，读取 `../../../data/README.md` 和对应 Markdown 模板。

规则和数据模板是权威来源；本 Skill 不重新定义状态、字段或作者权。

## 选择入口

- 已有正式闪念：恢复形成现场后，先辨析价值，再决定是否发展。
- 已失效或发酵闪念：只有用户主动重新打开时继续，并保留原状态历史。
- 成熟判断：直接进入认识完善，不制造闪念，也不等待认知保鲜期。
- 只是查询历史内容：退出本 Skill，按上下文召回协议回答。

## 工作流程

1. 读取当前对象及必要形成现场，明确它过去是什么，不把历史表达当作当前立场。
2. 由用户判断是否值得继续。Agent 可以指出重复、异常、冲突和可能价值，但不能代替用户裁决。
3. 只有当前判断确实依赖历史内容时，才召回少量、相关、可解释的上下文。
4. 确认值得继续后，围绕实际缺口推进：核心判断、必要理由、其他解释、边界或反例、以及未来可能发挥的作用。
5. 已经清楚的部分不重复询问；一次只推进一个会改变理解或决定的问题；不按固定问卷补齐内容。
6. 根据用户决定记录去向：放弃、保持未决、进入发酵，或形成永久认识候选。
7. 进入发酵时只保存一段忠实的自然语言备注，记录当时真实存在的原因、缺口或重启条件，不强制三项齐全。
8. 形成永久认识时，展示完整候选及真实形成依据。一次讨论允许产生零项、一项或多项候选。
9. 用户可以修改、拆分、合并或拒绝；只有用户认领后才创建正式认识或新修订版本。
10. 正式认识形成后，保留原始会话、闪念和全部历史，不自动建立通用语义关系。

## 认知保鲜期

- 当前初始默认是从正式闪念认领时开始的 48 小时，可按规则调整。
- 保鲜期用于及时恢复兴趣和隐含上下文，不要求把每张闪念转成永久认识。
- 活跃讨论不因计时到点而中断。
- 超期行为、重新激活和召回资格以规则层为准。
- 提醒与后台调度不由本 Skill 实现。

## 完成条件

- 用户对当前价值或下一步拥有最终判断；
- 闪念可以被放弃、保持未决、进入发酵或参与形成认识；
- 永久认识候选可以为零、一项或多项；
- 未经认领的候选没有成为正式认识；
- 召回和外部材料没有被误写成用户当前判断。
