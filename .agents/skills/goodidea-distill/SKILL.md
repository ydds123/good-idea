# 发展一个值得继续推敲的认识

判断并发展值得继续推敲的认识，或维护用户已经认领的永久认识。

## 权威与加载

`../../../规则/` 是产品语义的唯一权威。本 Skill 只负责路由、加载、编排和停止；任何摘要与规则冲突时，以规则为准。

1. 始终读取 `../../../规则/系统宪法.md`。
2. 读取 `../../../规则/内容对象.md` 中与正式闪念、永久认识和形成依据有关的内容。
3. 辨析闪念时执行闪念辨析协议；形成或修订认识时执行认识完善协议；停用认识时依据对象契约和用户最终决定处理。
4. 只有实际需要历史内容或外部材料时，才读取上下文召回或统一来源登记协议。
5. 涉及保鲜期、发酵或干预取舍时读取 `../../../规则/默认规则.md`。
6. 发生写入时，读取 `../../../数据/README.md` 和对应模板。

## 编排

1. 先识别用户是在处理闪念、直接形成认识、修订认识还是停用认识，并读取对应正式对象和必要形成依据。
2. 按所选协议推进，不把检索结果、外部材料或 Agent 推断冒充为用户当前判断。
3. 需要候选时，完整展示并等待用户认领；写入、版本和生命周期变化严格服从对象契约。
4. 用户尚未决定时保留合法未决结果；用户作出决定后记录去向和历史，不制造额外对象补齐流程。
5. 当前意图完成即停止，不反向创建原始思考记录，也不自动开启新的捕捉。

## 退出与交接

- 新想法仍在生成且用户要保护现场时，退出并交给 `goodidea-capture`。
- 只是查询历史时，退出并直接执行上下文召回协议。
- 只是保存外部材料时，退出并直接执行统一来源登记协议。
- 完成时确认用户保有最终判断，未认领候选没有转正，历史和对象身份没有被覆盖。
