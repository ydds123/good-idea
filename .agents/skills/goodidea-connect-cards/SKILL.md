# 连接卡片

普通永久卡片在接纳前已通过形成来源连接完成最小网络激活；本 Skill 不负责补做准入门禁。母题、行动和索引卡片仍按各自现有契约处理。没有值得建立的额外语义关系时，报告“当前无需新增语义连接”即可，不调用 `connect propose`，也不为了完成流程制造表面关系。

只有存在另一张合适的正式卡片时，才进入连接流程。读取两张正式卡片及其来源。关系必须表达可解释的语义，例如支持、冲突、限定、例证、演化、行动验证或索引入口，不能只因关键词相同而连接。

## 两阶段流程

1. 先判断是否存在合适的另一张正式卡片；不存在时结束并报告当前无需新增语义连接。
2. 存在合适对象时，说明候选关系、方向和理由。
3. 调用候选命令：

       uv run goodidea --root <仓库> connect propose --from-id <ID> --to-id <ID> --relation <关系> --rationale <理由>

4. 向用户展示候选并等待明确确认。
5. 确认后调用：

       uv run goodidea --root <仓库> connect accept --proposal-id <ID>

6. 运行 goodidea verify，确认双向链接、连接账本和索引一致。

不要自动接受连接，不要创建只停留在关键词层面的表面关系。额外语义连接为空不是错误，也不影响普通永久卡片已经完成的形成来源激活。
