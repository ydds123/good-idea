# 连接卡片

普通永久卡片在接纳前已通过形成来源连接完成最小网络激活；本 Skill 不负责补做准入门禁。母题、行动和索引卡片仍按各自现有契约处理。没有值得建立的额外语义关系时，报告“当前无需新增语义连接”即可，不调用 `connect propose`，也不为了完成流程制造表面关系。

## 两种进入方式

- **你主动提出**：你询问卡片关系，或希望建立支持、冲突、演化、例证等关系时进入。
- **form-permanent 确定性交接（2026-08-23 松海拍板）**：普通永久卡片接纳后，form-permanent 流程第 10 步强制交接本 Skill——评估对象 = 新卡 vs 既有知识网络；素材检索阶段已发现的关联素材可直接作为候选来源。

无论哪种进入方式，连接都须经 `connect propose` → 你确认 → `connect accept`，禁止未确认直接写入；无合适对象时报告“当前无需新增语义连接”即合规退出。

## 连接端点（2026-08-20 闪念连接通道拍板）

连接两端必须是已存在的**正式卡片、闪念或来源**，且类型组合在连接图（`contracts.CONNECT_GRAPH`）允许范围内：

- 正式卡四类互通（permanent/mother/action/index 之间任意）
- 闪念 ↔ 闪念
- 闪念 ↔ 来源

其余组合（正式卡 ↔ 闪念、正式卡 ↔ 来源、来源 ↔ 来源）暂无需求场景，不开放；CLI 会拒绝并报“连接起点/终点不是允许的连接端点”。愿景是各种类型卡片都支持双向连接——以后放开组合只改 `CONNECT_GRAPH`，本 Skill 无需再改。

只有存在合适的另一张可连接卡片时，才进入连接流程。读取两端卡片正文（闪念读触发情境/闪念内容/激活逻辑/演化记录；来源读快照与关联闪念）。关系必须表达可解释的语义，例如支持、冲突、限定、例证、演化、行动验证或索引入口，不能只因关键词相同而连接。

## 两阶段流程

1. 先判断是否存在合适的另一张可连接卡片；不存在时结束并报告当前无需新增语义连接。
2. 存在合适对象时，说明候选关系、方向和理由。
3. 调用候选命令：

       uv run goodidea --root <仓库> connect propose --from-id <ID> --to-id <ID> --relation <关系> --rationale <理由>

4. 向用户展示候选并等待明确确认。
5. 确认后调用：

       uv run goodidea --root <仓库> connect accept --proposal-id <ID>

6. 运行 goodidea verify，确认双向链接、连接账本和索引一致。

## 闪念连接的生命周期行为

- 两端正文都机械维护「## 连接」节（闪念在演化记录之后；来源在关联闪念之后，快照区不受影响）。
- 闪念转「已处理」归档时，连接**跟随闪念保留**（2026-08-20 拍板：不继承迁移到永久卡）；归档重写会自动更新两端正文里的 wikilink 指向新路径。
- 断开已接受的连接用 `connect disconnect`（必须带原因）。

不要自动接受连接，不要创建只停留在关键词层面的表面关系。额外语义连接为空不是错误，也不影响普通永久卡片已经完成的形成来源激活。
