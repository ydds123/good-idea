# 形成并审查永久类卡片

永久卡片只能由用户主动发起。Agent 可以通过苏格拉底式对话帮助用户完善判断；用户授权后，可以结构化用户表达，但不能新增观点。

## 不可越过的作者边界

- 可以从用户已经表达的中心判断中提炼一个典型标题；标题不得加入用户没有表达的新主张。
- 不替用户创造中心主张、理由、例子、边界、反例、行动或结论。
- 价值裁决是提问引导：Agent 呈现机会、结果贡献、维护成本的事实与问题，可以指出某变量趋零的事实，但不得代替用户裁决值不值得，也不得因裁决结果阻止用户坚持发起。
- 不把 Agent 的推断、反例、连接建议或审查意见放进草稿。
- 只有用户明确授权后，才可删除口语停顿与重复、调整已有表达顺序并整理成 Markdown；不得补入用户未表达的内容。
- 必须把结构化后的完整草稿展示给用户。用户未明确确认整份草稿时，禁止持久化。
- 用户只有一个想法时，进入苏格拉底式交流；坚持一次一个问题，每轮只问最关键的问题，根据用户上一轮回答继续追问，不一次抛出问题清单，也不替用户回答。
- 对话中的零散表达不是可发布正文。观点澄清后形成待确认草稿；在用户确认全文之前不调用写命令。
- 四种类型 permanent、mother、action、index 都遵守同一作者边界。

### 草稿写作质量（2026-08-13 教训沉淀）

草稿干瘪的根因不是信息少，而是把用户的语音流当数据压缩成结论，丢掉了让结论活着的肌理。三条机制与对策：

1. **搬运隐喻，不要翻译隐喻**：用户说"头牌再红，嫖资归妓院"（价值捕获）、"壁垒再深守的也是小池塘"（领域天花板）——隐喻是用户理解的载体，不是论点装饰。直接改写比喻会丢锚点，只剩抽象词。草稿保留用户原比喻，可在其旁补充机制说明。
2. **保留在场性**：用户表达里有"我"、有时间（"22年6月毕业，快4年了"）、有动作（"得趁这段时间找好跳板"）、有情绪（唉、说实话、头疼）。草稿删掉这些会变成无主体、无时间、无场景的命题陈述——最讽刺的是写一张"没有主体的主体性卡"。用户确认过的叙述段落可以整段保留进正文，不必全部转成命题。
3. **叙事不切成并列论点**：用户的理解是流动的（先讲经历、再总结教训、最后落到判断）。组织草稿时保留递进逻辑链（为什么失效→什么验证了失效→新范式→支撑条件→边界），不要切成"观点一、观点二"的平级块。用户明确反馈"平级堆放没有逻辑关系"和"只有论点没有血肉"都是这类问题的信号。

**草稿写作的两步顺序（用户确认的流程）**：第一步，先确保上下文全面、充分、无遗漏（对应覆盖检查：把本轮用户全部实质表达列清单核对入稿）；第二步，拿到充分上下文后，基于第一性原理进入 EchoLayer 模式写作——多层语义折叠与回声递归，保持结构感、流动性与逻辑张力，检测潜语、结构信号与非线性语义折叠。顺序不可颠倒：没有充分的上下文，EchoLayer 只是空转；只有上下文没有 EchoLayer，草稿就会干瘪。

判断标准：**草稿应让用户感到"这是我说的，而且比我说得更清楚"**——既保留讨论的语调环境，又完成了结构化和精炼。用户说"进入我的模式"即指此。干瘪检查：草稿是否还能让未来的自己"重新活一次"当时的判断，而不只是"读到"一个结论。

## 审查标准

普通永久卡片先裁决值不值得，再审查合不合格，两个判断都通过才可形成候选。

### 第零问：值不值得（投资裁决）

永久卡不是收藏，是面向未来任务的认知节点。一张卡从闪念变成永久卡，就开始占用有限的维护注意力和网络噪声预算——所以成卡前先按目标函数裁决：这张卡未来介入判断、行动或创作的期望净价值是否为正（目标函数与 EV 六变量定义见 `设计方案/永久卡片整体设计逻辑.md` 第二节，此处不重复全文）。发起时的"想转"往往带着当下热度，这一问是冷静层，不是形式。

裁决发生在澄清出中心判断之后（输入是一句能说清这张卡主张什么的话，不需要完整草稿），结合用户当前工作、已有关卡与长期方向提问，不空泛。只问三个快问快答：

- **机会**：未来什么任务会调用它？它与用户当前或长期的问题域（工作项目、研究主题、写作方向）是否相关？
- **结果贡献**：用了它相比不用，能改变什么判断或结果？它是否只是常识或一次性感想？
- **生命周期成本**：转了它以后，你愿意为它做维护吗（核验、修订、连接）？

可找到性、有效性、可理解性、可应用性取决于卡片怎么写，由合格审查与写作质量把关，不在第零问重复提问。三问中任一答不上来或明显模糊时，默认留在闪念空间：多转一张低价值卡的代价是永久网络噪声，少转的代价只是未来重新表达。

**第零问是双通道**：答案同时服务裁决（值不值得）和草稿（内容素材）。机会、结果贡献的回答里常含正文素材（调用场景、使用价值、具体做法），这些实质内容必须回填到最终草稿，不能因为属于"裁决问答"就丢弃。裁决是"判断值不值得"的通道，不是"内容过滤"的通道。

裁决是提问引导，不是 Agent 单方决定：Agent 呈现事实（如"听起来未来调用机会很低"），结论由用户拍板；裁决结果不阻止用户坚持发起，发起权始终在用户。裁决为不值得的闪念，停留在闪念空间等待发酵：闪念空间是低门槛的珍珠养殖场，永久空间是高门槛的展示台，很多珍珠只是等待契机激活（李继刚材料就是去年4月的内容，今年8月才被激活成形成来源），不转永久卡不等于无价值，只是当前不值得占用永久卡的维护预算。闪念按自身生命周期被回顾处理；若未来在真实任务中再次遇到同一问题，重新发起即可——重新表达就是重新评估的通道，不是误杀。澄清中形成的更清晰表达，可由用户决定是否更新回原闪念卡（走 capture revise），让这次思考的产出回流闪念本身。

### 第一问：合不合格（五项必要条件）

- 普通永久卡片只有同时满足以下条件才可形成候选：只有一个清楚的中心判断；脱离原对话仍能理解；说明为什么成立或值得保留；写明适用边界、限制或可被推翻的条件；至少有一个经用户确认的真实形成来源。
- 区分形成来源与外部依据：形成来源说明这张卡从哪里形成，使用 `--from-ids`；外部依据说明哪些来源支持、限制或反驳判断，使用 `--source-ids`。同一来源可以兼任，但不能用只有 `--source-ids` 的资料引用冒充形成连接。
- 形成来源可以是闪念、来源、既有正式材料或本轮直接表达。只有本轮表达可用时，不制造闪念；请用户确认一句具体说明所回应问题、经验或现实情境的形成说明，写入仓库外临时文件并使用 `--direct-source-file`。不要保存完整聊天原文。
- 行动卡包含行动和结果反馈入口；母题卡保持开放；索引卡说明组织目的。
- 审查意见、Agent 推断和反例只留在对话，不进入用户草稿。

## 素材检索策略（2026-08-15 用户拍板）

形成永久卡时，素材来源不限于用户口述与外部资料：**未发酵的闪念是待激发的认知资产**（酿酒比喻：酒曲需要时间；实证：AI 生图实践抓手卡跨度一年多——2025-04 李继刚内容→AI生图→控制论与科学方法论，由激发点串起）。检索素材时不漏掉它们。

1. **读取顺序**：先读永久卡片（同主题/关联主题的既有判断）→ 永久卡无匹配时，再读闪念空间（待发酵的念头）。
2. **闪念检索策略**：不全文扫描——按索引列渐进匹配（note-database 视图：标题/状态/标签/日期，或按关键词检索标题），命中可能相关的条目后再读正文判断。
3. **闪念的两种素材角色**：形成来源（规则 6 允许，闪念可作为形成来源）与关联素材（永久卡网络激活时的待连接对象）。
4. **发酵观**：检索命中的未发酵闪念不视为无价值——它是"待激发"；可列为形成来源候选或连接候选，由用户裁决是否使用。

## 流程

1. 确认用户已主动发起永久类卡片。只有口述草稿时，每轮简短定位上一回答带来的变化，再从定义、因果、证据、边界或反例中选择一个最关键问题；不预先倾倒问题清单。
2. 按审查标准帮助用户形成自己的判断：先用苏格拉底式对话澄清出中心判断（一句能说清这张卡主张什么），再做第零问投资裁决（机会、结果贡献、生命周期成本三问，由用户拍板）；裁决值得后，再按五项必要条件审查。普通永久卡片同时列出候选形成来源及各自作用，请用户确认；未达到标准时等待用户补充，不生成写入候选。达到标准也不等于获得创建授权。
3. 根据用户完整表达提炼标题，并把用户已表达的内容结构化为 Markdown；只删填充词（嗯/啊/这个）、合并重复和调整顺序，不新增观点。
4. **覆盖检查（草稿定稿前必做）**：把本轮对话中用户全部实质表达列成清单（定义、理由、调用场景、边界、反例、行动），逐项核对草稿是否入稿；**任何遗漏项必须拿出来问用户是否写入，不许 Agent 自行判定"不重要"而丢弃**。覆盖检查清单与草稿一并展示，用户确认后才视为最终草稿。Agent 有权力整理，没有权力丢弃。
5. 展示完整待确认草稿。只有用户明确确认全文没有问题，才把它视为最终草稿。
6. 用户确认完整草稿后，把最终草稿保存到仓库外临时文件。普通永久卡片还需确认形成来源，然后先运行 `uv run goodidea --root <仓库> permanent propose --help`，按当前 CLI 帮助创建候选。若只有本轮表达可用，把用户确认的一句具体形成情境保存到仓库外临时文本文件；不要保存完整聊天。用户直接提交自己的完整草稿时可使用逐字模式；草稿第一行必须是唯一的 `# 标题`。若用户已在确认草稿的同时明确声明“草稿确认后直接创建”（预授权），在同一命令中附加 `--preauthorize-accept`；预授权必须由用户主动声明，Agent 不得自行推断或代为解释，其余确认参数照常必需。
7. 未预授权时：向用户报告候选标题、路径和形成来源，然后立即结束当前 Agent 回合。不得把候选形成前的“确认全文”或提前授权解释成正式接纳，也不得在同一回合继续查看或调用 `accept`。已预授权时：`--preauthorize-accept` 让 propose 在同一调用内完成全部 accept 校验并直接创建正式卡片，候选不残留；Agent 向用户报告正式卡片标题、路径和形成来源，不再进入本步的等待。
8. 只有未预授权、且用户看到候选结果后发送一条新的消息再次明确要求正式创建，才运行 `uv run goodidea --root <仓库> permanent accept --help` 并按当前 CLI 帮助接纳该候选。
9. 接纳完成后运行 `uv run goodidea --root <仓库> verify`。普通永久卡片的用户认知正文必须保持确认草稿不变；CLI 可以在正文末尾机械添加“形成来源”导航区。该区不属于用户创作内容。

`permanent propose` 不授权 Agent 创作新观点。旧候选若缺少新门禁要求的形成来源确认，必须撤销并重新提案，不能静默补齐。错误或过时的待处理草稿先查看 `permanent withdraw --help` 再撤销，不能接纳。

正式卡片创建后的 `permanent revise` 和 `permanent feedback` 也只能提交用户亲自写下并确认的内容；执行前查看对应 `--help`。CLI 可以机械添加区块、列表标记和时间戳、规范化边界换行，但不得改变用户措辞。Agent 仍然只能评估，不能维护正文。
