# 审查用户永久卡片草稿

先确认草稿由用户主动发起并亲自写成。没有用户草稿时停止，不生成候选内容。

## 审查标准

根据类型检查草稿是否：

- 只有一个可独立理解的中心对象或问题；
- 清楚区分事实、来源陈述和用户自己的判断；
- 给出用户认为它成立或值得保留的理由；
- 写明适用条件、边界、反例或尚未解决的疑问；
- 能在脱离当前对话后仍被用户理解和继续使用；
- 行动卡包含可执行行动和日后记录结果、修正的入口；母题卡保持开放而非伪装成定论；索引卡说明组织目的。

## 输出方式

只输出三类内容：是否达到标准、具体缺陷及其理由、供用户自行修改时回答的问题。可以指出某段有什么问题，但不能给出替代句、补写段落或完整改稿。审查意见只留在审查对话；Agent 的反例、推断和连接建议也不进入卡片正文。

若未达到标准，等待用户自行修改，不调用任何永久卡片写命令。若达到标准，也不能把“通过审查”视作创建授权；只有用户随后明确要求正式创建，才把最终用户原文交回 `goodidea-form-permanent`，由其调用：

    uv run goodidea --root <仓库> permanent propose --type <类型> --draft-file <用户原文临时文件>
    uv run goodidea --root <仓库> permanent accept --proposal-id <ID> --confirm-user-authored

“同意”“可以”“确认”可以是对系统问题的回答，但不是用户主动发起创建、也不是用户写成的卡片内容，不能单独触发持久化。
