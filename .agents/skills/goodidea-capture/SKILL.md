# 保护正在发生的认识

目标是以尽可能小的干预保护正在生成的认知现场，而不是立即证明、分类或完善它。

## 先加载规则

1. 始终读取 `../../../rules/constitution.md`。
2. 读取 `../../../rules/objects.md` 中的原始思考会话、闪念候选、正式闪念和形成依据。
3. 读取 `../../../rules/protocols.md` 中的捕捉、上下文召回和统一来源登记协议。
4. 需要决定提问或召回程度时读取 `../../../rules/defaults.md`。
5. 发生正式保存时，读取 `../../../data/README.md` 和对应 Markdown 模板。

规则和数据模板是权威来源；本 Skill 只负责编排当前对话。

## 工作流程

1. 确认用户明确进入捕捉；普通聊天不得被静默记录。
2. 立即开始或续接原始思考会话，先保存触发消息，再做其他处理。
3. 持续追加全部可见对话。即使出现分支，也不在认知发生时拆成多个会话。
4. 优先回应用户正在思考的内容。附件、来源处理和历史召回只能作为背景。
5. 用户仍在展开时继续听；只有关键歧义会产生实质不同理解时才问一个问题。
6. 用户说“只记录”“先别整理”或同义表达时，确认已保存并结束；不提问、不提炼、不生成候选、不建议下一步。
7. 在自然结束点，只有用户主动要求，或确有清晰认知种子时，才询问是否需要闪念候选。
8. 候选应包含可唤起内容的标题、核心内容、真实触发情境和形成依据。它可以表达本次对话中真正共同形成的新理解，但必须与原始对话区分。
9. 用户可以修改、合并、拆分或拒绝候选；只有用户认领后才保存正式闪念。
10. 完成捕捉后停止，不自动进入 `goodidea-distill`。

## 干预取舍

- 小而清晰：简短确认，允许直接保存。
- 小而模糊：最多询问一个决定性歧义。
- 大而清晰：等待用户表达完整，再讨论保存。
- 大而模糊：询问先保存当前现场，还是继续展开。

这只是启发式。用户明显还在表达时，不用矩阵打断用户。

## 可插拔能力

- 用户带材料表达想法：先保护表达，再按统一来源登记协议处理材料。
- 用户只保存外部资料：退出本 Skill，直接执行来源登记协议。
- 历史内容只有在用户要求、用户主动指出关联，或少量召回能避免明显误解时才进入上下文。
- 来源或召回失败时继续当前表达，不要求用户等待或重说。

## 完成条件

- 原始思考现场已完整保存；
- 记录窗口已结束或明确保持开放；
- 正式闪念数量可以为零、一张或多张；
- 未经用户认领的候选没有成为正式对象；
- 没有自动进入价值辨析或永久认识流程。
