# 保护正在发生的认识

以尽可能小的干预保护正在生成的认知现场。

## 权威与加载

`../../../规则/` 是产品语义的唯一权威。本 Skill 只负责路由、加载、编排和停止；任何摘要与规则冲突时，以规则为准。

首轮在同一次工具调用批次中整读以下四份文件，之后不重复读取已在上下文中的内容：

1. `../../../规则/系统宪法.md`
2. `../../../规则/内容对象.md`
3. `../../../规则/协作协议.md`
4. `../../../规则/默认规则.md`

实际涉及历史内容、行动或外部材料时，在同一轮内一次读齐对应材料和协议。创建正式记录时优先调用 `python3 工具/new.py ...` 或 `python3 工具/capture.py start ...`；工具不可用时，按 `数据/README.md`、模板和规则手工完成。

## 编排

1. 先核对用户是否已明确进入捕捉。若没有，不创建任何捕捉数据；普通聊天中的可选建议按默认启发式处理。
2. 明确进入后，执行 `python3 工具/capture.py start --session <会话标识> --title "<标题>"`，从触发消息开始完整执行捕捉协议。进入后不再逐轮写文件：适配器可用时，每回合的用户可见消息和 Agent 最终回复由它追加（只含可见文本），stop 所在回合落盘后由它提交；适配器不可用时，改用 `python3 工具/capture.py append --session <会话标识>` 手工补写；脚本也不可用时，按模板手工写入 `数据/记录/闪念/原始思考记录/`。
3. 遇到“只记录”或同义表达，执行 `python3 工具/capture.py stop --session <会话标识>`，并遵守协议中的立即停止条件。
4. 到达自然结束点后，按协议判断是否提出候选；候选讨论及其决定完成、捕捉窗口真正结束时，再执行 `python3 工具/capture.py stop --session <会话标识>`。候选和正式对象的边界以对象契约为准，提交能力是否启用不影响记录关闭。
5. 捕捉完成即停止。用户明确要求登记或处理行动时直接执行行动协议；只有用户明确要求继续辨析、完善或维护既有永久卡片时，才交接 `goodidea-distill`。

完成时确认：现场保存完整、窗口状态明确、未认领候选没有转正，也没有自动进入后续认知流程。
