# 捕捉闪念与认知现场

先读仓库根目录的 AGENTS.md 与 schema.md。当前存在 active、reviewing 或 paused 捕获会话时，本 Skill 优先于关键词和附件类型。保留用户原始表达，只修复明显转写错误，不擅自扩写论证或包装成成熟认识。

## 一、本质定义（矩阵定位）

**闪念 = 松海跨域连接的浓缩结果**——脑回路能瞬间连接两个不相关事物的本质（快速得到结果），但过程是压缩的。

**矩阵定位**（两个维度）：

- 大小：点（一个念头）→ 线（串起几个点）→ 面（覆盖一片框架）→ 体（立体结构）
- 充分度：充分表达（已串起来、想清楚）vs 未充分表达（有框架但没串起来，存在挖掘点/可能性空间）

**Agent 的角色 = 展开 + 校验**：把压缩的过程展开（找上下文、把挖掘点挖开、串起来），展开的同时校正结果。**展开的目标 = 从不充分到充分**（矩阵的「充分」维度）。完善表达 = 校正认知。

### 矩阵定位判断标准

**大小（点/线/面/体）——听结构信号：**

- 点：一句话能说完，无展开结构，无连接点
- 线：一个念头带出 2-3 个关联点（想法 + 依据/例子）
- 面：有框架——多个点组成结构
- 体：多个面互相关联（跨域连接成体系）

判断信号：出现「然后/另外/还有」等连接词 → 至少是线；提到多个子主题、有「本质/框架/体系」类词 → 面；引用了过去的卡片/来源、说「这里边其实包含东西蛮多的」→ 面/体；跨域连接（两个不相关领域）→ 体。

**充分度——听表达信号：**

- 不充分：说「挺重要」但没说清为什么；提到概念不展开（「卡帕西那个闪念」）；探索语气多（其实/本质/对吧/怎么说呢）；自我修正多（「到 10 月底……或者说 9 月底」）；出现能连过去的点（「就按照我们前边整理的」）——这些点就是挖掘点
- 充分：有完整的因为所以；自问自答闭环；边界清楚

### 四象限深度参数

| 象限 | 找料 | 展开 | 校验 |
|---|---|---|---|
| 小×充分 | 不找 | 不展开 | 忠实整理，轻确认 |
| 小×不充分 | 轻找（相关卡 1-2 张） | 一次一问补全，把点说圆 | 呈现补全后的点 |
| 大×充分 | 全找（相关卡+来源） | 结构化梳理（脉络+连接） | 完整脉络确认 |
| 大×不充分 | 全找+跨系统（llm-wiki、历史会话） | 深度展开：挖掘点逐个挖开、串起来、补全、逻辑线 | 展开后完整呈现，松海纠正（校正环节） |

## 二、主线流程（六步）

**深度规则**：越大、越不充分的闪念挖得越深；越小、越充分的做得越轻（轻到跳过 3-4 步直接落盘）。

1. **接住**：原样记录，不丢、不改、不打断——现场保护。识别强闪念信号后立即保护，判级不延迟保护：

       uv run goodidea --root <仓库> capture start --text <用户原话> --context-ref <链接或文件> --transaction-id <稳定ID>

2. **定位**：听完一轮后按判断标准判断大小+充分度 → 向松海确认定位结果（一句话：「这个想法我判断是【面×不充分】——有框架但没串起来，要挖开几个点，对吗？」）→ **确认后才进入找料**。

3. **找料**：按定位找相关上下文——检索锚 = 表达里的专有名词/概念/过去的引用；渐进式读取（先索引/文件名 → 命中读正文），不全量；大×不充分跨系统（llm-wiki、Hermes 历史会话）；检索范围含闪念空间（含已处理/发酵中/已放弃）、溯源空间、有意思空间、待办空间（含已过期）、设计方案、永久空间；**松海明令禁止的目录（如 Agent Client）绝不检索**。文件和链接只做可访问性检查并按需读取，结果与轻量指纹写回运行时会话；不运行来源 preview、图片处理或全库验证：

       uv run goodidea --root <仓库> capture context-check --session-id <会话ID> --ref <上下文> --status <readable|unreadable|partial> --fingerprint-file <临时JSON> --transaction-id <稳定ID>

4. **展开**：把不充分展开到充分——加工对象 = 原始语料 + 检索内容。识别挖掘点（提到但没展开的东西）→ 每个点补「是什么」+ 揪「为什么在这里出现/和什么连」→ 按松海原始逻辑顺序串接（不重排）→ 补充融入原文不标注 → 终点检查：每个提到的概念都展开了吗？逻辑线都揪出来了吗？能独立唤起上下文吗？（对照下方加工检查清单）。一次一个问题；用户不想继续展开时立即进入校验，不强迫追问。新表达原样追加：

       uv run goodidea --root <仓库> capture append --session-id <会话ID> --text <用户新表达> --transaction-id <稳定ID>

5. **校验**：呈现完整脉络（不是碎片清单）→ 松海确认/纠正 → 纠正 = 新输入，回到 3-4。**任何新表达都会使旧候选失效并回到交流；重新 propose 后再展示最新完整脉络。** 明确询问最新完整清单是否已覆盖本轮内容，只有用户确认后才 finalize：

       uv run goodidea --root <仓库> capture propose --session-id <会话ID> --manifest-file <临时候选JSON> --transaction-id <稳定ID>
       uv run goodidea --root <仓库> capture finalize --session-id <会话ID> --proposal-id <最新候选ID> --confirm-discussion-complete --transaction-id <稳定ID>

6. **落盘**：确认是完整、充分思考的闪念后存下；去向由松海裁决：闪念 / 永久卡 / 留档讨论。落盘前必须松海确认。

**加工检查清单**（展开/校验环节对照执行）：

- 不拆平铺要点：保留原话表述与原话逻辑
- 框架 + 血肉 + 逻辑流动，缺一不可
- 针对性补充描述（概念展开 + 逻辑线）融入原文、不刻意标注
- 逻辑线揪出来：说明「为什么把这两件事关联」
- 有结构但不编号切碎，也不能没结构——语义标签式
- 卡片要能独立唤起上下文
- 落盘前必须松海确认（确认门禁）
- 提问纪律：提问与目标关联，成形即停

**manifest 契约**：内部 manifest 使用 `format_version: 2`，锚点字段（`source_anchors`/`source_anchor`/`trigger_anchor`/`activated_logic`/`source_boundary`）契约见 schema.md「临时捕获会话」节，此处不重复；正式卡片渲染为"可点击溯源链接 + 论证说明"单元，不得另设纯链接的"关联来源"节；无外部来源时 `source_anchor` 明确写"松海本轮口述，无外部来源"，不得伪造依据。用户修正已生成闪念的来源锚点时，展示"链接 + 说明 + 边界"完整结果并确认后调用 `capture revise-source-anchors`；不得直接编辑 Markdown。

## 三、情况表（与主线正交，任何时刻可能发生）

**聊到一半**：

- 暂停：capture pause，记录全留，下次 resume 接着聊
- 放弃：capture discard（必须松海明确说），零正式写入；任务异常不等于放弃，下次恢复即可
- 中断恢复：capture resume，接着上次的脉络继续

       uv run goodidea --root <仓库> capture pause --session-id <会话ID> --transaction-id <稳定ID>
       uv run goodidea --root <仓库> capture resume --session-id <会话ID> --transaction-id <稳定ID>
       uv run goodidea --root <仓库> capture status --session-id <会话ID>
       uv run goodidea --root <仓库> capture discard --session-id <会话ID> --confirm-user-abandoned --transaction-id <稳定ID>

**只想记一下**（小×充分的快捷通道）：

- 用户明确说"只记录，不讨论"，或对象是有意思内容时，接住后直接落盘，跳过找料/展开/校验：

       uv run goodidea --root <仓库> capture flash --text <原始表达> --context <情境>

  将 flash 替换为 interesting。**存待办走 goodidea-todo**（B 原则 + 四段信息架构在那边）。需要幂等重试时复用同一个 transaction-id。正式单次记录完成后运行 goodidea lint；多轮捕获前台不运行，finalize 和后台维护完成后再统一 verify。

**转永久卡**：

- 不自动转；落盘时松海裁决去向
- 讨论出了结论：先问转不转；转 → 交接 goodidea-form-permanent；不转 → 结论用松海原话 capture revise，讨论原文 capture discuss 留档
- 讨论留档：只记原文，不转化、不结构化摘要；**同一卡片始终追加同一档案文件**（单文件时间线，讨论从上次停处延续）；Agent 不生产摘要——原文归原文（discuss），结论归结论（用户确认的结构化），不得把 Agent 整理的观点当作"演化记录"贴到卡片上
- finalize 后自动把后台来源任务交给 goodidea-record-literature；捕获阶段到此结束，绝不自动进入永久卡片

## 四、底线总纲（任何时候不能破）

- 松海的话就是松海的话：不改意思、不替你总结、不加没表达的观点
- 正式记录不创建内容摘要，也不在 Frontmatter 保存 `summary`
- 落盘前必须松海确认
- 讨论留原话，不留 Agent 总结
- 引用的来源标清楚
- 捕获阶段不自动进永久卡
