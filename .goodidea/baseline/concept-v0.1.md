# 概念说明文档

**Good idea**

一种借助大语言模型增强个人判断与行动能力的认知系统模式。

这是一份概念说明文档，设计之初就是为了让你把它复制粘贴给自己的 LLM Agent，例如 OpenAI Codex、Claude Code、OpenCode / Pi 等。它的目标是传达整体构想；至于具体如何实现，则由你和 Agent 在协作中共同完成。

**核心构想**

大多数人与 LLM 和知识打交道的方式，都围绕一个简单过程展开：你上传资料、提出问题，LLM 检索相关信息，再为你生成答案。

这种方式确实有效，但存在一个问题：答案可以越来越容易获得，人的判断却不一定因此变得更好。LLM 可以替你总结一本书、比较几个观点、生成一套方案，却未必能让你真正理解这些内容，也无法保证这些认识会在未来的问题中被重新调用，更无法代替你进入实践、承担结果并根据反馈修正认识。

久而久之，外部系统积累了大量资料和答案，人却可能仍然停留在原地。系统知道得越来越多，使用者反而越来越依赖系统。

这里提出的思路有所不同。

LLM 不只是在问题出现时检索资料并生成答案，而是要帮助人**逐步构建并持续维护一套长期存在的个人认知系统**。这个系统由一组结构化、相互链接的 Markdown 文件构成，位于原始资料、人的思考与现实行动之间。

当你添加一份新资料时，LLM 不只是建立索引，留待日后检索。它会阅读资料、提取关键信息，并把这些内容与现有认识进行比较：寻找能够相互支持的观点，标记彼此冲突的结论，识别它与个人问题之间的关系，并帮助你把真正重要的部分转化为永久卡片。

但这个过程不能完全交给 LLM。

一条信息为什么重要，它改变了什么原有认识，你最终相信什么，又准备如何行动，这些判断必须由人参与完成。LLM 可以提供草稿、反例、证据和可能的联系，却不能替人拥有判断，也不能替人承担判断造成的结果。

一条认识也不是整理完成后便宣告结束。它需要在未来的问题中被调用，在行动中接受检验，再根据现实反馈得到补充、修正、拆分、合并或者淘汰。

这正是二者之间最关键的区别：

**Good idea 是一套让外部知识与人自身能力共同产生复利的认知系统。**

外部系统会逐渐积累可靠的知识卡片、明确的生成关系、不断演化的问题簇和长期存在的母题；人也会在反复解释、判断、行动和复盘中，逐渐形成更敏锐的问题意识、更稳定的判断能力和更丰富的实践经验。

如果只是外部系统变得越来越强，而人的理解力、判断力和行动能力不断减弱，那不是 Good idea 的成功，而是一种被自动化掩盖的失败。

你不需要亲自完成所有整理工作。格式转换、文件命名、来源标注、重复检查、双向链接、索引更新、状态同步和跨页面维护，都可以由 LLM 承担。

但你需要亲自参与真正影响认知的部分：用自己的语言解释一条认识，判断它与自己有什么关系，辨别事实与推断，处理矛盾和不确定性，寻找反例，决定是否采纳，并在现实中验证它。

在实际使用中，你可以一边打开 LLM Agent，一边打开 Obsidian。LLM 根据你们的对话修改文件，你则实时查看修改结果：阅读永久卡片，检查不同认识之间的联系，沿着问题簇继续思考，并观察某个长期母题如何随着实践不断演化。

**Obsidian 是认知工作台，LLM 是系统维护者，卡片网络是外部思考环境，而你是判断者和行动者。**

**这种模式可以用于许多不同场景。例如：**

- **个人生活：**追踪自己的目标、健康状况、心理状态和自我成长。记录重要经历、判断过程和行动结果，逐渐理解自己反复面对的问题，而不只是积累一份个人档案。
- **研究**：用数周乃至数月时间深入研究一个主题。持续阅读论文、文章和报告，把资料转化为永久卡片，逐步形成问题簇，并让其中的核心判断随着新证据不断演化。
- **阅读一本书**：读完一章，处理一章；不追求完整复述，而是识别真正改变自己认识的内容，用自己的语言写成卡片，并把它们连接到已有问题和经验之中。读完全书后，留下的不是一份更短的书籍摘要，而是一组已经进入个人认知网络、能够在未来被调用的思想成果。
- **企业或团队**：建立一套由 LLM 协助维护的团队认知系统，资料来源包括讨论记录、会议逐字稿、项目文档、用户反馈和决策结果。系统不仅保存团队知道什么，还保存为什么这样判断、采取了什么行动，以及现实结果是否支持原来的判断。
- **产品设计、职业规划、写作、决策复盘、课程学习和兴趣研究**：凡是需要长期积累认识，并希望这些认识最终改善判断、行动、决策或作品的场景，都适合采用这种模式。

**系统架构**

Good idea 的文件架构就是系统架构。

系统中的每一个顶层目录都对应一种明确的认知状态。资料、想法和行动不会被统一塞进一个知识库，而是根据它们当前所处的阶段，进入不同空间。文件从一个空间流向另一个空间的过程，就是信息逐渐转化为个人认识的过程。

整个系统由闪念空间、溯源空间、有意思空间、待办空间和永久空间构成。永久空间内部再分为永久卡片、母题卡片、行动卡片和索引卡片。

**闪念空间**

闪念空间用于承接刚刚出现、尚未完成处理的个人想法。

它可能是突然出现的灵感，阅读过程中产生的疑问，对某件事形成的临时判断，也可能是一条想要继续追踪的线索。

这里保存的不是成熟认识，而是思考正在发生的痕迹。记录时不要求完整、不要求分类，也不要求立刻证明它是正确的。它唯一需要做到的，是让未来的自己能够重新理解当时究竟想到了什么。

闪念进入系统后，默认处于“待处理”状态。创建两天后仍未处理的闪念，自动转为“已失效”；已经转化为永久卡片，或者已经确认无须继续处理的闪念，标记为“已处理”。

闪念空间是缓冲区，不是长期收藏夹。它的任务是防止刚刚出现的想法消失，而不是让所有想法永久存活。

**溯源空间**

溯源空间用于保存书籍、论文、文章、访谈、报告、网页、视频逐字稿等外部材料。

进入这一空间的材料应尽可能保持原貌。系统可以补充标题、作者、日期、网址、页码、章节、获取时间等来源身份，但不能用摘要替代原文，也不能把 LLM 的解释写回原始材料。

溯源空间保存的是“外部世界说过什么”，而不是“我最终相信什么”。永久卡片可以引用溯源材料，但原始材料本身不会因为被处理而移动到永久空间。

这样，任何永久卡片都能沿着来源标识返回原文，重新核对语境、证据和作者本意。即使未来判断发生变化，事实依据仍然存在。

**有意思空间**

有意思空间用于保存日常生活中发现的、暂时还说不清价值，却引起了注意的内容。

它可能是一个现实案例、一段对话、一张图片、一种产品设计、一个异常现象，也可能是一件看起来与当前问题无关，却让人产生轻微触动的事情。

有意思空间与闪念空间的区别在于：闪念记录的是自己脑中刚刚产生的东西；有意思空间记录的是外部世界中刚刚吸引了自己的东西。

它与溯源空间的区别在于：溯源空间保存具有完整来源身份的材料；有意思空间允许只保存一个局部片段、一个现场案例或一次偶然发现。

这些内容不必立即被解释。它们首先作为现实样本存在，未来可能成为永久卡片的例证、行动卡片的观察材料，或者母题卡片中的新线索。补全来源后，也可以进一步进入溯源空间。

**待办空间**

待办空间用于保存未来某个时刻需要处理、但当前不能或不应立即处理的事情。

它的作用是解除记忆负担，不承担知识沉淀。待办完成后即可关闭或删除；只有当处理过程产生了可以复用的判断、经验或方法时，才进一步生成行动卡片。

待办与行动卡片不能混为一谈。待办记录“还有什么事情没有完成”，行动卡片记录“我在什么情境下作出了什么判断，采取了什么行动，结果如何，以及未来应该如何调整”。

前者随着任务完成而失去价值，后者可能随着复盘积累而不断增值。

**永久空间**

永久空间保存已经经过理解，能够长期参与个人思考的内容。

外部材料不会直接进入永久空间。闪念、文献笔记、有意思的案例和行动经验，只有在被重新理解、用自己的语言表达，并与既有认知发生关系之后，才会在这里形成新的卡片。

永久空间不是档案库，而是个人认知系统真正发生生长的地方。

永久卡片是默认类型。它表达一个能够独立理解、独立引用和继续发展的完整判断。它不是原文摘抄，也不是资料摘要，而是自己在理解外部信息后形成的思想单元。

母题卡片承载长期思考、反复出现的底层难题。它不是一张更长的永久卡片，也不是某个主题下的内容汇总。它保存的是一个仍然开放的问题，以及围绕这个问题不断出现的判断、证据、矛盾、行动和阶段性答案。

行动卡片保存具有复盘、校验和进化价值的实践。它记录当时面对的情境、掌握的信息、作出的判断、采取的行动、实际结果和后续修正。普通任务不会自动成为行动卡片，只有能够改善未来判断和行动的经历才值得进入这里。

索引卡片本身不产生新的观点。它把一组已经存在的永久卡片组织成某个场景、问题或主题的入口，解决卡片增长之后的检索与迷路问题。它不是固定分类，也不追求完整覆盖，而是随着卡片网络生长持续调整。

在文件层，永久空间可以进一步映射为永久卡片、母题卡片、行动卡片和索引卡片四个子目录。卡片类型由目录位置确定，标签只负责补充场景、领域和状态，不再承担主要分类职责。

**规范与执行层**

内容空间之外，系统还需要规范文件、Skills 和日志。

规范文件规定空间边界、卡片格式、来源规则、状态流转、自动化范围以及哪些判断必须由用户确认。它相当于 Good idea 的系统宪法。

Skills 承载具体操作。它们读取规范，识别当前材料属于什么对象，执行相应工作流，并把结果写入正确空间。Skill 不拥有最终判断权，只负责稳定地组织流程、生成候选结果和完成机械维护。

日志记录系统发生过的操作，包括闪念处理、资料录入、永久卡片生成、关系建立、索引调整、行动复盘和系统巡检。日志面向时间，卡片空间面向内容，二者不应合并。

**基本操作**

Good idea 的基本操作由一组 Skills 承载。

每个 Skill 对应一种稳定、可以重复执行的认知动作。它不仅规定 LLM 应该修改哪些文件，也规定这次操作为什么发生、用户需要参与哪些判断、操作完成后系统应当发生什么变化。

这些 Skills 可以单独使用，也可以相互衔接。一次完整的资料处理通常会经过记录文献笔记、转化为永久卡片和接入卡片盒；一个突然出现的想法，则通常从捕捉闪念笔记开始，再视其价值决定是否继续转化。

**捕捉闪念笔记**

当一个想法突然出现，而你正在阅读、交谈、工作或者处理其他事情时，可以使用这个 Skill 把它暂时放入闪念空间。

闪念可能是一条灵感、一个疑问、一个尚未展开的判断，也可能是一条想要继续追踪的线索。它的作用不是立即把想法加工成熟，而是在尽量不打断当前活动的情况下，留下足够的思考痕迹，使你之后仍然能够重新理解它。

一个典型流程是：你用一句话、语音或者随手输入的方式记录想法；LLM 修复明显的转写错误，保留你的原始表达，必要时追问或补充它产生的情境；随后创建一张闪念笔记，记录创建时间、处理状态和失效时间，并把它放入闪念空间。

LLM 不应在这个阶段擅自扩写论证、补充结论或者把模糊想法包装成成熟认识。闪念的完成标准不是表达完整，而是未来重新看到时，仍然知道自己当时想到了什么，以及为什么想继续处理它。

闪念只是一张给未来自己的提醒，不是长期保存的知识。你需要定期回顾闪念空间，在产生背景尚未遗忘之前，决定把它转化为永久卡片、转为待办、补充为有意思的案例，或者让它失效。

如果一个想法出现时已经表达完整，也已经明确了它与现有认识的关系，就可以跳过闪念阶段，直接转化为永久卡片。

**记录文献笔记**

当你阅读一本书、一篇论文、一篇文章、一份报告，或者处理访谈、课程、视频逐字稿等外部材料时，可以使用这个 Skill 建立来源，并记录其中真正值得继续思考的内容。

它的作用不是把原文压缩成一份更短的摘要，而是保存“原作者说了什么、依据是什么、你为什么注意到它”，为后续形成永久卡片提供可靠材料。

一个典型流程是：LLM 识别资料的标题、作者、日期、出处、网址、章节或页码等来源信息，将原始材料保存到溯源空间并建立稳定的来源身份；随后阅读资料，与你讨论其中真正值得关注的观点，记录必要的原文位置、作者论证和你的初步理解，最后生成文献笔记并链接回原始资料。

文献笔记不需要平均覆盖整份资料。简单资料可能只留下一个值得使用的判断，复杂资料则可能需要记录论证结构、方法、证据、限制和多个关键位置。判断标准不是摘要是否完整，而是这些记录能否帮助你准确理解资料，并在以后形成永久卡片时迅速回到原始语境。

直接引文必须保持原意并标明位置。作者观点、事实陈述、用户理解和 LLM 推断需要明确区分。LLM 可以帮助概括，却不能把自己的解释伪装成作者原意。

一份资料可能产生多条文献笔记，也可能影响多张已有卡片。更合适的方式通常是一次处理一份资料，由你检查 LLM 是否抓住了真正重要的内容，并指出哪些部分改变、补充或者挑战了已有认识。

文献笔记仍然属于溯源阶段。它可以长期保留，用于返回原文和核对证据，但只有经过进一步理解并转化为独立判断后，其中的内容才会进入永久空间。

**审查永久卡片**

当一张永久卡片已经形成初稿，准备进入永久空间时，可以使用这个 Skill，检查它是否真正完成了认知转化。

它的作用不是润色文字，也不是替你把卡片补充完整，而是确认：这是否已经成为一个能够独立存在、经得起质疑，并由你理解和承担的判断。

一个典型流程是：LLM 先区分其中哪些内容来自外部资料，哪些属于你的理解，哪些只是 AI 推论；随后检查卡片是否只有一个中心主张，能否脱离原始现场独立理解，是否具备必要的理由、条件、边界和来源，以及与已有思想的关系是否清楚。

如果存在推理跳跃、概念含混、证据不足、前提隐藏、结论过度延伸或反例无法解释等问题，LLM 应指出问题在哪里、为什么构成缺陷，并提出检验问题，引导你重新思考，但不能替你补写核心观点和成立理由。

如果卡片包含多个独立判断，应当拆分；如果只是摘要、改写或作者观点的转述，应判定为尚未完成认知转化。AI 提出的反例、联系和推论只能保留在审查意见中，不能直接写入正文。

LLM 可以寻找反例、检查逻辑和提出候选联系，但不能替你决定相信什么。凡是涉及个人立场、价值取舍、现实行动和判断后果的内容，都必须由你确认。

操作完成后，原始资料仍然保留在溯源空间。作为生成起点的闪念会标记为已处理，并链接到新卡片。永久卡片则获得明确的来源身份，但此时它还只是一个形成完成的思想单元，下一步仍需要接入卡片盒。

**回顾与处理**

捕捉闪念和记录文献笔记只负责产生中间材料。如果系统没有稳定的回顾机制，这些空间会不断积压，最终退化为另一个收集箱。阿伦斯强调在遗忘记录缘由之前处理闪念和文献笔记，Good idea 中的两天失效规则，本质上也是在保护这段短暂的语境。

当你准备处理闪念、文献笔记、有意思的内容或者行动记录时，可以使用这个 Skill 查看尚未完成认知转化的材料，并决定它们的下一步去向。

一个典型流程是：LLM 按创建时间、时效状态、关联问题和潜在价值整理待处理内容；你逐条决定继续展开、转化为永久卡片、改为待办、补充来源、暂时搁置或者标记失效；LLM 随后调用对应 Skill 完成流转，并同步更新状态、链接和日志。

这个 Skill 不负责判断内容本身是否正确，而是确保系统中的中间材料不会长期滞留。它把“捕捉”与“处理”分开，使你可以在想法出现时快速记录，又能在注意力完整时集中完成真正的理解与判断。

至此，基本操作才形成闭环：捕捉闪念保存思考痕迹，记录文献笔记保存外部依据，回顾与处理决定材料去向，转化为永久卡片形成个人认识，接入卡片盒让认识进入关系网络。

“有意思空间”和“待办空间”不必各自创建复杂 Skill。它们可以采用类似闪念的轻量记录能力：有意思空间保存暂时无法解释、但值得保留的外部现象；待办空间保存未来需要完成的事务。只有当其中的内容需要进入长期认知系统时，才调用转化为永久卡片或行动卡片的 Skill。否则，系统会把普通收藏和任务管理错误地抬升为认知加工。

**巡检（Lint）**

定期让 LLM 对卡片网络进行健康检查，重点寻找：

- 不同卡片之间相互矛盾，却没有被明确标记的判断；
- 已被新资料或实践结果推翻的过时认识；
- 没有与任何问题、行动或其他卡片发生联系的孤立内容；
- 已被多次提及，却尚未形成独立永久卡片、问题簇或母题卡的重要认识；
- 缺失、错误或者只停留在关键词层面的表面连接；
- 已经形成判断，却长期没有进入行动、验证和反馈环节的内容。

LLM 也很擅长发现值得继续追问的问题，识别长期没有进展的母题，并建议应当寻找的新资料或可以进行的现实验证。

随着卡片网络不断扩大，定期巡检可以维持整个系统的健康状态，避免它逐渐退化为一个只进不出、只有收藏而没有思考的资料仓库。

**索引与日志**

随着卡片网络持续增长，两个特殊文件可以帮助 LLM 和你在其中导航。二者承担着不同职责。

**index.md 面向内容。**

它是卡片网络全部内容的目录。每个页面都以链接形式列出，并附有一句话摘要；还可以选择性地添加日期、卡片类型、关联问题和引用资料数量等元数据。

目录可以按照永久卡片、问题簇、母题卡、资料来源和实践记录等类别组织。每完成一次资料摄取或卡片更新，LLM 都会同步维护它。

回答问题时，LLM 首先读取索引，找到相关页面，然后再深入阅读具体内容。

在中等规模下，例如约 100 份资料、数百张卡片，这种方式已经能够支持稳定调用，也无须立即搭建基于嵌入向量的 RAG 基础设施。

**log.md 面向时间。**

它是一份只允许追加、不允许改写的历史记录，记载系统在什么时间发生了什么，包括资料摄取、问题探索、判断形成、行动反馈和系统巡检。

一个实用技巧是：让每条记录都以统一格式开头，例如：

**[2026-08-03] reflect | 如何判断一条知识是否真正有用**

这样一来，就可以使用简单的 UNIX 工具解析日志。例如：

grep "^## \\[" log.md | tail -5

这条命令可以显示最近五条记录。

日志呈现了个人认知系统的演化时间线，也能帮助 LLM 理解近期形成了哪些判断、采取了哪些行动，以及哪些问题仍在等待反馈。

可选项：命令行工具

到了某个阶段，你可能会希望开发一些小工具，让 LLM 更高效地操作卡片网络。

最明显的需求，是为永久卡片、问题簇和母题卡建立一个搜索引擎。规模较小时，索引文件已经足够；但随着卡片网络扩大，你会需要更完备的搜索能力。

[qmd](https://github.com/tobi/qmd) 是一个不错的选择。它是一款面向 Markdown 文件的本地搜索引擎，结合了 BM25、向量检索和 LLM 重排序，而且所有计算都在本地设备上完成。

它既提供 CLI，方便 LLM 通过 Shell 调用，也提供 MCP 服务器，使 LLM 可以把它当作原生工具使用。

你也可以自行搭建一个更简单的版本。等到需求真正出现时，让 LLM 协助你边试边写一个朴素的搜索脚本即可。

搜索工具的作用只是降低查找成本。它能够帮助系统找到可能相关的卡片，却不能判断这些卡片之间究竟是什么关系，更不能替人决定哪条认识值得相信。

**实用技巧**

**Obsidian Web Clipper** 是一款可以把网页文章转换成 Markdown 的浏览器扩展，非常适合将新资料快速导入原始资料库。剪藏只是摄取的起点，不意味着资料已经进入长期认知网络。

**把图片下载到本地。** 在 Obsidian 的“设置 → 文件与链接”中，将“附件默认存放路径”设为固定目录，例如 raw/assets/。然后进入“设置 → 快捷键”，搜索“Download”，找到“下载当前文件中的附件”，再为它设置一个快捷键，例如 Ctrl+Shift+D。剪藏一篇文章后按下快捷键，文章中的全部图片便会保存到本地。这样，LLM 可以直接查看图片并理解其中的图表、结构和上下文，不必依赖可能失效的网址。

**Obsidian 的图谱视图**适合观察卡片网络的整体形态。你可以看到哪些问题聚集了大量认识，哪些永久卡片成为连接不同领域的枢纽，哪些卡片长期处于孤立状态。但图谱是否繁茂并不代表系统是否有价值，真正的标准仍然是这些连接能否改善判断与行动。

**Marp** 是一种基于 Markdown 的幻灯片格式，Obsidian 提供了相应插件。它适合把已经形成的卡片与判断进一步组织成可以交流、汇报或公开表达的作品。

**Dataview** 是一款可以查询页面 Frontmatter 的 Obsidian 插件。如果 LLM 在卡片中添加了 YAML Frontmatter，例如卡片类型、状态、来源、关联问题、验证情况和最后更新时间，Dataview 就可以据此生成动态表格和列表。

卡片网络本质上只是一个由 Markdown 文件组成的 Git 仓库，因此天然拥有版本历史、分支管理和协作能力。它不仅可以保存当前结论，也可以保留一个判断如何形成、如何被修正以及为什么被放弃的过程。

**为什么这种模式行得通**

维护认知系统最令人厌烦的部分，并不是阅读、思考和实践，而是那些琐碎的管理工作：

整理格式，核对来源，更新交叉引用，识别重复内容，保证摘要反映最新认识，记录新证据与旧判断之间的冲突，以及维持数百张卡片之间的一致性。

人们之所以放弃知识系统，往往不是因为知识没有价值，而是因为维护负担的增长速度超过了系统能够带来的现实收益。

LLM 不会因为重复检查链接而厌倦，也能够在一次操作中检查和修改多个文件。它可以显著降低那些不产生理解、却不断消耗注意力的机械成本，让卡片网络得到持续维护。

但 Good idea 并不试图消除所有摩擦。

用自己的语言重新表达，判断什么值得留下，辨别证据是否可靠，处理彼此冲突的观点，寻找反例，作出选择并承担结果，这些过程虽然费力，却正是理解和能力形成的地方。把这些摩擦也交给 LLM，等于在降低使用成本的同时取消了人的学习过程。

人的职责是提出真实问题，筛选资料，确认关键认识，形成判断，进入行动，并根据结果修正自己。

其余机械工作，则交给 LLM。

这一构想在精神上与卢曼的卡片盒一脉相承。卡片不是信息的容器，而是可以被重新调用、相互连接并继续生长的思考成果；记录的目的也不是积累更多知识，而是让阅读、思考、写作和实践成为同一个持续推进的过程。

记录不仅要来自阅读，也要来自行动、决策、结果与复盘，然后必须用自己的语言形成永久笔记，并让新认识进入已有的关系网络

过去真正困难的地方，是人既要完成思考，又要承担庞大的日常维护工作。维护一旦中断，卡片就会失去连接，索引会逐渐过时，系统最终重新退化为资料仓库。

现在，LLM 可以接过机械维护，却把理解、判断、行动和方向权留在人身上。

**说明**

本文有意保持抽象。它描述的是一种模式，而非某个具体实现。

确切的目录结构、Schema 规范、卡片格式、自动化边界和工具选择，都取决于你的问题领域、个人习惯以及使用的 LLM。

上文提到的所有组成部分都是可选的、模块化的：有用的就采用，无关的就忽略。

例如，你可能只需要永久卡片，尚未形成稳定的问题簇和母题卡；你的卡片网络规模可能很小，只靠索引文件就足以使用，无须建立搜索引擎；你可能不需要图谱、幻灯片或复杂的 Frontmatter，只需要保证每条认识能够被理解、被找到并在现实问题中重新使用。

正确的使用方式，是把这份文档交给你的 LLM Agent，再与它协作，落地出一个真正适合你的版本。

这份文档唯一的任务，就是把这种模式讲清楚。

剩下的，由你和 LLM 共同完成。
