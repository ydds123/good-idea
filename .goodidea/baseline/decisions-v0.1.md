# Good idea v0.1 决策冻结

冻结日期：2026-08-04

1. 从概念出发独立实现，不复用或迁移 `my-wiki`、`llm-wiki` 的代码、结构、数据和工作流。
2. 完整保留闪念、溯源、有意思、待办、永久五个空间；永久空间保留永久、母题、行动、索引四类卡片。
3. [已由第 19 项覆盖] 溯源空间没有两个子目录。一份来源就是一份包含可编辑文献笔记区和受保护原文快照区的 Markdown 文件。
4. 输入附带链接时，想法进入闪念空间，正文 Markdown 快照和本地图片进入溯源空间，并双向链接。
5. 只有链接时，Agent 必须先阅读并提出内容相关的保存动机问题；用户回答后才持久化。放弃回答则零写入。
6. 默认只保存来源快照和待处理骨架，不自动生成作者观点或用户理解。
7. 永久卡片正式接纳前，用户必须用自己的语言重新解释；纯确认无效。
8. v0.1 七个核心 Skills 均需最小但真实可用；Skills 负责对话，CLI 负责确定性写入。
9. v0.1 仅供当前用户、macOS 本机使用；网页与微信公众号为首批来源，本地文件以后再做。
10. 每个成功原子事务自动创建 Git 提交；回滚使用非破坏性 revert。
11. Skills 位于项目内 `.agents/skills/`。
12. 真实验收包含 Karpathy gist、一篇公开公众号文章、用户本人一次保存动机和至少一张永久卡片的重新解释与接入。
13. 飞书概念说明 revision 30 与本文件共同构成 v0.1 基线；不回写飞书，执行期间不跟随新想法漂移。

## 2026-08-07 用户确认的基线修订

14. 永久卡片只能由用户主动发起；Agent 以一次一个问题的苏格拉底式对话帮助完善观点。用户授权后，Agent 可以删除口语停顿与重复、调整顺序、提炼标题并结构化为 Markdown，但不得增加新观点；全文必须经用户确认后才能写入。
15. 五个空间的内容文件统一使用 `YYYY-MM-DD-标题.md`。稳定 ID 只作为隐藏内部身份，不进入标题、文件名和人类可读索引。
16. Obsidian UI 配置纳入 v0.1 产品基线。机器参数继续服务 CLI 完整性、去重和状态机，但在 Obsidian 正常阅读界面中默认隐藏；稳定配置托管，临时 workspace 状态不托管。
17. [已由第 19 项覆盖] 溯源笔记只持久化规范链接；原始分享链接仅用于当次抓取。人类阅读顺序固定为“文章标题 → 原文快照 → 文献笔记 → 关联闪念”。
18. 正式卡片进入永久空间、索引和状态账本即视为接入卡片网络。首张卡片或暂时没有合适关联对象的卡片可以保持零语义连接；只有存在有意义的关系时才提出候选并由用户确认，不为完成流程强行造边。
19. 删除“文献笔记”这一认知层。溯源空间一份来源只保存来源元数据、原文快照、本地图片和机械维护的关联闪念；人的即时观点、疑问和念头进入闪念空间，连接并思考多个念头后形成的判断进入永久空间。此项修订覆盖冻结概念文档中关于文献笔记中间层的旧描述。

## 2026-08-09 用户确认的基线修订

20. 五个空间的正式内容与人类可读索引不保存或展示内容摘要，废弃 Frontmatter `summary` 字段。Git 事务中的同名操作说明只属于状态账本、日志和提交信息，不属于卡片内容。
21. 文档权威顺序固定为：`AGENTS.md` 定义人机权责，`schema.md` 定义机器可验证契约，项目 Skills 定义边界内的对话流程，`README.md` 负责解释，`.goodidea/baseline/` 保存历史依据。发生冲突时停止写入并交由用户决定。
22. 永久卡片由用户主动发起并确认完整草稿后，先通过 `permanent propose` 形成隐藏候选；只有用户随后明确要求正式创建，才能通过 `permanent accept` 进入永久空间。
23. 概念基线作为历史输入不静默改写；用户确认的后续修正追加在本文件，并同步当前 README、AGENTS、Schema、Skills、实现和测试。
24. 闪念捕获是独立入口阶段：用户想法是主信息，附件、链接和文件只是本轮想法的上下文。它们只做可访问性检查和按需读取，不能把主流程切换为来源摄取。
25. 一次捕获会话可以经过多轮交流产生多张闪念。系统先在不进入 Git 的运行时目录保护认知现场，再生成可反复修正的闪念候选清单；新增表达使旧候选和确认失效。
26. 用户确认最新完整清单已经覆盖本轮该记录的内容后，CLI 才原子创建正式闪念。会话支持暂停、恢复、放弃、失败重试和整批非破坏性回滚；永久卡片阶段不因本修订自动启动或改变。
27. 来源快照、图片、关系、索引和全库验证在捕获完成后通过可恢复后台任务执行。来源失败、图片失败、上下文变化和任务中断不得回滚正式闪念；新闪念可以在安全原子边界抢占后台维护。
28. 临时原始会话默认不永久托管。finalize 后只保留短期恢复窗口，来源维护完成且至少 24 小时后清理；正式闪念和来源继续进入聚焦 Git 历史。
