# 真实试运行协议

## 目的

用现有对话入口和两个项目 Skill 执行捕捉、辨析、认识完善和按需召回，观察规则是否真的减少摩擦。试运行不要求 Kernel 或独立应用。

## 保存范围

用户已经决定保存完整试运行对话，但保存位置必须服从内容身份：

1. 捕捉类试运行在 `数据/记录/原始思考会话/` 创建原始思考 Markdown，完整对话以该会话文件为唯一事实；`验证/试运行记录/` 中的记录只引用它并保存观察。
2. 有意思登记、辨析、认识完善、召回和来源登记等非捕捉试运行，不创建原始思考会话；全部可见对话直接保存在对应的 `验证/试运行记录/TRIAL-*` 记录中。
3. 两类记录都保存用户与 Agent 的全部可见消息、消息顺序、时间，以及用户主动带入且对理解必要的上下文。
4. 不用摘要替代消息原文，也不默认匿名化。
5. 不保存隐藏推理、系统提示、工具内部日志或对用户不可见的中间内容。
6. 只引用实际形成的闪念、认识和来源，不用空对象补齐结果。
7. `TRIAL-*` 是评测证据标识，不是第六类认知对象，也不成为正式对象的替代入口。

普通聊天不会被静默收录。只有用户明确开始捕捉或续接已有捕捉会话时，才建立原始思考会话；明确开始非捕捉试运行时，只建立 `TRIAL-*` 验证记录。

## 一次试运行的顺序

1. 读取系统宪法和本次涉及的对象、协议。
2. 根据当前意图进入 `goodidea-capture`、`goodidea-distill`，或直接调用有意思登记、来源登记、上下文召回协议；不为评测而额外打断。
3. 按本协议保存完整对话，并按数据模板保存用户实际认领的对象。
4. 在 `验证/试运行记录/` 写一份 `TRIAL-*` 记录；捕捉类引用会话文件，非捕捉类在记录内包含完整可见对话。
5. 把发现分类为单次异常、启发式、可调默认、协议或硬边界问题。
6. 单次摩擦只进入待观察项；重复出现后再讨论规则修改或能力固化。

## 观察维度

- 捕捉是否及时，是否漏掉可见消息；
- 用户是否被来源处理、分类问题或候选询问打断；
- “只记录”是否真正停止加工；
- Agent 提出的问题是否改变了理解，还是只为填字段；
- 闪念候选是否延续用户逻辑，被接受、修改、拆分或拒绝；
- 是否允许零产出和多产出；
- 发酵备注是否忠实且足够支持重启；
- 永久认识是否属于用户、能够独立理解并带真实依据；
- 召回是否相关、是否减少重复解释、是否制造噪声；
- 来源失败和召回失败是否影响当前表达；
- 哪些动作反复出现并确实值得机械化；
- Skill 是否误触发、漏触发，或在交接时继续了用户没有要求的流程。

## 固化准入

一个动作进入 Kernel、Skill 或应用候选前，至少需要说明：

- 它在哪些真实试运行中重复出现；
- 当前手工做法造成了什么具体摩擦或风险；
- 固化后保护哪个对象边界或改善哪个可观察结果；
- 删除这项能力是否会损害规则和数据的独立成立。

无法回答以上问题的能力继续留在直接对话中，不进入实现。
