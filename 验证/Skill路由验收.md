## 对抗与混合路由用例

| 场景或请求 | 预期入口 | 验收重点 |
|---|---|---|
| 用户分享文章并说“这里把效率当成价值，我觉得有点不对”，但未要求记录 | 普通对话 | 不触发 capture，不创建会话或文件；自然停顿处最多建议一次 |
| Agent 在自然停顿处建议“要不要把刚才这点记下来？”，用户回答“先不用” | 普通对话 | 建议本身不启动 capture；拒绝后不写入、不重复建议 |
| “把这篇文章的核心观点存成我的永久认识。” | `goodidea-distill`；实际材料按需进入来源登记 | 外部观点不能直接冒充用户认识；只有用户表达、理解并认领自己的完整候选后才能创建认识 |
| “记下这个新想法，顺便看看它和《关于职业选择的闪念》是不是一回事。” | 先 `goodidea-capture`，再显式交接 `goodidea-distill` | 先保护当前触发消息；比较旧闪念是松海明确要求的后续意图，不是自动沉淀 |
| 捕捉进行中，用户说“顺便把上次那条闪念处理一下” | 当前会话继续保存可见对话，并显式交接 `goodidea-distill` | 不因话题分支实时拆出第二个原始会话；旧闪念仍按自身对象历史处理 |
| “重新打开已经失效的《某条闪念》，我想再判断一次。” | `goodidea-distill` | 保留旧状态历史；按松海决定重新激活并使用当前默认窗口 |
| “把《某项永久认识》按我刚才的新判断修订一下。” | `goodidea-distill` | 展示修订候选；松海认领后追加版本，不创建“已修订”状态 |
| “《某项永久认识》以后不要再作为我的当前判断了，停用它。” | `goodidea-distill` | 松海明确决定后转为 `已停用`；不删除版本和形成依据 |

## Skill 1 行为用例

### 显式进入与建议边界

- 只有松海明确要求记录、捕捉、保存或续接时，才创建或续接原始思考记录。
- 普通聊天中的明显种子最多在自然停顿处建议一次；确认前没有任何捕捉写入。
- 用户拒绝或忽略建议后，本轮上下文继续作为普通对话。

### 只记录

1. 创建或续接原始思考记录。
2. 保存全部可见表达。
3. 用户说“只记录”后只确认保存。
4. 不提问、不生成候选、不交接第二个 Skill。

### 长表达与关键问题

- 松海明显还在展开时不总结、不拆分原始思考记录。
- 只有答案会改变理解或下一步时才问一个关键问题。
- 仅仅为了补标题、分类或字段时不提问。

### 多个认知种子

- 原始对话继续保存在同一份原始思考记录中。
- 只有用户主动要求或确有清晰种子时，才在自然结束点询问候选。
- 候选可独立修改、合并、拆分或拒绝；未经用户认领不进入正式数据。

### 附件和失败降级

- 附件处理不能抢占用户表达。
- 来源获取和历史召回失败时，当前会话继续。
- 不编造未读取材料中的内容。

## Skill 2 行为用例

### 价值不足

- 用户可以直接决定放弃。
- 内容和历史继续保留，默认退出召回。
- Agent 不要求把它解释成成熟观点。

### 发酵

- 只记录一段忠实的自然语言备注。
- 不强制同时填写保留理由、缺口和重启条件。
- 未来出现时明确标注尚未完成。

### 形成永久认识

- 先完成用户认为必要的价值辨析和认知发展。
- 展示完整候选和真实形成依据。
- 候选可以包含对话中新形成的理解，但不能伪装成用户原有观点。
- 松海认领后才正式创建；原始思考记录和闪念继续保留。

### 成熟判断直接进入

- 不创建形式性的闪念。
- 不适用闪念保鲜窗口。
- 只处理独立理解仍缺少的内容。

### 修订与停用

- 修订先展示完整候选，用户认领后追加新版本，旧版本继续保留。
- 停用只改变生命周期状态，不删除版本、形成依据或历史。
- 外部材料、召回结果和 Agent 推断都不能直接成为用户的当前认识。

## 交接验收

- `goodidea-capture` 完成后停止，除非用户明确要求继续辨析、形成、修订或停用认识。
- 混合请求中先保护当前正在发生的表达，再执行用户已经明确提出的后续意图。
- 捕捉中途切换主题不导致原始思考记录按语义实时拆分。
- `goodidea-distill` 不反向复制原始思考记录，也不把检索结果变成新闪念。
- 有意思登记、来源登记和上下文召回可以和两个 Skill 协作，但不能控制用户结论。
- 删除、重命名或合并 Skill 时，对象身份、状态和数据历史仍然成立。
