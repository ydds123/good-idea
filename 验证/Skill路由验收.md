| “继续昨天那次原始思考，我还有一点没说完。” | `goodidea-capture` | 续接既有会话，不创建重复现场 |

## 对抗与混合路由用例

| 场景或请求 | 预期入口 | 验收重点 |
|---|---|---|
| 用户分享文章并说“这里把效率当成价值，我觉得有点不对”，但未要求记录 | 普通对话 | 不触发 capture，不创建会话或文件；自然停顿处最多建议一次 |
| Agent 在自然停顿处建议“要不要把刚才这点记下来？”，用户回答“先不用” | 普通对话 | 建议本身不启动 capture；拒绝后不写入、不重复建议 |
| “把这篇文章的核心观点存成我的永久卡片。” | `goodidea-distill`；实际材料按需进入来源登记 | 外部观点不能直接冒充松海的永久卡片；只有松海表达、理解并认领自己的完整候选后才能创建永久卡片 |
| “记下这个新想法，顺便看看它和《关于职业选择的闪念》是不是一回事。” | 先 `goodidea-capture`，再显式交接 `goodidea-distill` | 先保护当前触发消息；比较旧闪念是松海明确要求的后续意图，不是自动沉淀 |
| 捕捉进行中，用户说“顺便把上次那条闪念处理一下” | 当前会话继续保存可见对话，并显式交接 `goodidea-distill` | 不因话题分支实时拆出第二个原始会话；旧闪念仍按自身对象历史处理 |
| “重新打开以前决定不再发展的《某条闪念》，我想再判断一次。” | `goodidea-distill` | 只有松海明确重新打开，才从 `已放弃` 回到 `待辨析`；保留原去向和 Git 历史 |
| “把《某项永久卡片》按我刚才的新判断修订一下。” | `goodidea-distill` | 展示修订候选；松海认领后更新当前正文，旧版由 Git 保留 |
| “《某项永久卡片》以后不要再作为我的当前判断了。” | `goodidea-distill` | 松海明确决定后在正文开头自然说明；不删除内容和形成依据 |

## 行动直接协议用例

以下是验收断言，不重新定义行动对象。对象身份、字段、状态和召回后果以 [`规则/内容对象.md#行动`](../规则/内容对象.md#行动) 为准，登记顺序以 [`规则/协作协议.md#行动登记与处理协议`](../规则/协作协议.md#行动登记与处理协议) 为准。

### 新建与更新

- 明确的行动、待办或任务请求进入行动协议；没有明确承诺的材料、建议或可能方向不进入正式行动。
- 明显重复的未完成行动更新原记录；不能确定时不猜测合并。
- 验收记录只检查“要做什么”和执行所需信息是否足够，不以补齐格式字段为目标。

### 完成、取消与提醒

- 完成、取消、过期等测试输入，必须按照对象契约更新原记录的当前状态和实际结果，不删除历史。
- 未完成行动的召回结果必须符合对象契约和默认规则；本文件不另列召回值域。
- 有期限但未单独设置提醒时，不得声称提醒已经存在；提醒能力的执行结果需单独验证。
- 行动登记不触发两个核心 Skill，也不从材料或 Agent 建议中自动生成。

## Skill 1 行为用例

### 显式进入与建议边界

- 只有松海明确要求记录、捕捉、保存或续接时，才创建或续接原始思考记录。
- 普通聊天中的明显种子最多在自然停顿处建议一次；确认前没有任何捕捉写入。
- 用户拒绝或忽略建议后，本轮上下文继续作为普通对话。

### 只记录

1. 创建或续接原始思考记录。
2. 保存全部可见表达。
3. 用户说“只记录”后只确认保存。
4. 不提问、不生成候选、不交接第二个 Skill。

### 长表达与关键问题

- 松海明显还在展开时不总结、不拆分原始思考记录。
- 只有答案会改变理解或下一步时才问一个关键问题。
- 仅仅为了补标题、分类或字段时不提问。

### 多个认知种子

- 原始对话继续保存在同一份原始思考记录中。
- 只有用户主动要求或确有清晰种子时，才在自然结束点询问候选。
- 候选可独立修改、合并、拆分或拒绝；未经用户认领不进入正式数据。

### 附件和失败降级

- 附件处理不能抢占用户表达。
- 来源获取和历史召回失败时，当前会话继续。
- 不编造未读取材料中的内容。

## Skill 2 行为用例

本节只检查路由后的对话行为。闪念卡片和永久卡片的对象契约以 [`规则/内容对象.md`](../规则/内容对象.md) 为准；辨析和完善顺序以 [`规则/协作协议.md`](../规则/协作协议.md) 为准。

### 闪念卡片状态

- 对每一种对象契约允许的状态决定，测试“松海明确决定后才更新”；没有决定时不自动改变。
- 测试进入发酵、放弃、形成永久卡片和重新打开等路径时，检查写入内容、去向和关联链接是否符合对象契约。
- 测试时间经过、相关性变化或 Agent 判断时，确认它们不会单独制造状态变化。
- 查询闪念卡片时，检查召回结果是否符合对象契约与默认规则，不在本文件重新列出状态优先级。

### 价值不足

- 用户可以直接决定放弃。
- 决定后按对象契约更新当前状态和去向，内容和历史继续保留，默认退出召回。
- Agent 不要求把它解释成成熟观点。

### 发酵

- 松海确认后按对象契约记录发酵决定和自然语言去向。
- 不强制补齐对象契约未要求的字段。
- 未来重新出现时明确标注尚未完成。

### 形成永久卡片

- 先完成松海认为必要的价值辨析和认知发展。
- 展示完整候选和真实形成依据。
- 候选可以包含对话中新形成的理解，但不能伪装成松海原有观点。
- 松海认领后才正式创建；原始思考记录和闪念卡片继续保留，相关联动按对象契约执行。

### 成熟判断直接进入

- 不创建形式性的闪念。
- 不制造用于过渡的状态或倒计时。
- 只处理独立理解仍缺少的内容。

### 修订与停用

- 修订先展示完整候选，松海认领后按对象契约更新当前正文，旧版由 Git 保留。
- 不再作为当前判断时按对象契约增加自然语言说明，不删除正文、形成依据或 Git 历史。
- 外部材料、召回结果和 Agent 推断都不能直接成为松海的当前判断。

## 交接验收

- `goodidea-capture` 完成后停止，除非用户明确要求继续辨析、形成、修订或停用永久卡片。
- 混合请求中先保护当前正在发生的表达，再执行用户已经明确提出的后续意图。
- 捕捉中途切换主题不导致原始思考记录按语义实时拆分。
- `goodidea-distill` 不反向复制原始思考记录，也不把检索结果变成新闪念。
- 行动、有意思、来源登记和上下文召回可以和两个 Skill 协作，但不能控制松海的承诺或结论。
- 删除、重命名或合并 Skill 时，对象身份、自然语言去向和 Git 历史仍然成立。
