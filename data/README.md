# 数据层

数据层只回答“已经保存了什么”，不定义对象应该意味着什么。

## 混合数据模式

```text
data/
├── records/       Markdown：人能够直接阅读和修订的认知事实
│   ├── sessions/  原始思考完整对话
│   ├── flashes/   正式闪念
│   ├── insights/  永久认识及版本历史
│   └── sources/   外部来源身份与快照记录
├── system/        JSON：机械支撑状态
│   ├── ids/       稳定 ID 登记
│   ├── candidates/临时候选
│   ├── events/    幂等与操作事件
│   ├── index/     可重建索引
│   ├── cache/     可重建缓存
│   └── background/后台处理状态
├── templates/     Markdown 事实格式示例
└── legacy/        旧项目只读位置声明
```

### Markdown 是认知事实

- 原始思考必须保存完整可见对话，不能只存摘要。
- 闪念和永久认识保存用户实际认领的内容。
- 来源记录保存身份、原始引用和实际快照历史。
- 人不需要运行程序就能理解已经保存的内容。

### JSON 只做机械支撑

- JSON 可以帮助稳定寻址、去重、幂等、排队和加速检索。
- 索引、缓存和后台状态删除后应当可以重建。
- JSON 不得保存一份与 Markdown 竞争的“正文真相”。若两者冲突，以 Markdown 事实和不可变事件为调查起点。
- 临时候选即使保存在 JSON，也不会因此成为正式内容对象。

当前没有活动 Kernel。Agent 可以依据规则和模板直接保存 Markdown；等真实使用证明需要确定性写入时，再设计最小执行能力。

## 文件命名

- 正式记录以稳定 ID 开头，例如 `SES-20260925-001.md`。
- 文件名可以附加短标题，但 ID 不随标题或路径改变。
- Markdown 内部保存完整身份、状态和时间；路径只是组织方式，不是对象身份。
- 模板展示最小结构，不要求为缺失信息编造内容。

当前没有确定性写入器时，Agent 先检查同类对象在当天已经使用的序号，选择下一个未占用的 `NNN`，并在写入前再次确认目标文件不存在。发生冲突时重新读取现有文件并选择新序号，不覆盖已有对象。这个约定只是临时机械做法，不改变任何对象语义。

## 旧项目参考

`legacy/reference.json` 只声明旧项目的位置和冻结提交。新系统不得在该目录复制旧数据，也不得调用旧业务代码。未来需要旧内容时，通过独立只读适配器按需读取。
