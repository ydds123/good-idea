# Good Idea v0.16

Good Idea 是一个帮助松海保护思考现场、辨析闪念并沉淀阶段性认识的个人认知系统。

这一版只追求两个目标：**简洁**与**灵活**。

- 简洁：松海只需要表达、判断和确认，不必理解系统内部结构。
- 灵活：规则不依赖某个界面、Skill、应用或存储程序，可以根据真实使用调整。

## 当前结构

```text
松海与 Agent
     │
     ├── 依据 规则/ 协作
     │
     └── 把已经发生的事实保存到 数据/

规则/       产品语义、权责、协议与可调默认
数据/       人类可读的 Markdown 事实
验证/       场景推演、试运行方法与观察结果
文档/       产品定义与设计背景
.agents/    两个核心 Skill 的项目级入口
```

当前没有活动 Kernel，也没有应用层。现有技术原型保存在 Git 分支
`prototype/kernel-v0`，不参与当前运行规则。

## 权威边界

- `规则/` 是产品规则的唯一权威位置。
- `数据/` 只记录事实，不定义产品语义。
- `验证/` 只验证规则，不创造规则。
- README、Skill、产品文档和未来实现只能引用规则，不能各自维护同义副本。
- 原始设计方案是重建时的设计输入，不是项目运行依赖。
- 旧项目 `../good-idea` 只读保留，用于历史参考，不是本项目的地基。

## 当前核心

系统承认四类正式内容对象：

1. 有意思；
2. 正式闪念；
3. 永久认识；
4. 外部来源。

原始思考记录是闪念生成过程的完整记录，归属于 `闪念/原始思考记录/`，不是与闪念并列的正式内容对象。闪念候选是临时草稿，也不是正式内容对象。

## 当前工作方式

1. 新想法捕捉使用 `goodidea-capture`，原始思考记录保存于闪念目录内部。
2. 闪念辨析、认识形成、修订与停用使用 `goodidea-distill`。
3. 两个 Skill 都先加载 `规则/` 中的对应权威规则。
4. 有意思登记、来源登记和上下文召回是直接协议能力，不单独扩展核心 Skill 数量。
5. 直接通过对话试运行，并按 `验证/试运行协议.md` 保存完整记录。

完整产品定义见 `文档/两个核心Skill产品定义.md`；它解释设计意图，但不覆盖 `规则/` 中的现行规则。
